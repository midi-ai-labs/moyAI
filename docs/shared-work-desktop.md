# DesktopのHubプロジェクト

Hubのプロジェクトは、Desktopの通常のプロジェクト一覧から開きます。同じプロジェクトに参加する人で、会話・仕事・成果を共有できます。別のPCへ依頼するだけなら、このPCのモデル設定やローカルプロジェクトの作成は不要です。

## 初回の接続

1. 「チームに参加する」からHub管理者の `hub-config.moyai-join` を読み込みます。設定済みDesktopでは「moyAI Hub」→「PCの接続」→「Hubの設定ファイルを読み込む」を使います。既存のDirect AI設定や実行権限は変わりません。
2. このPC固有の鍵とWindowsユーザー名で参加を申請します。管理者が申請元を確認し、PC名を付けて許可すると自動で接続します。同じWindowsユーザー名でも別PCは別登録です。
3. 管理者がこのPCをプロジェクトの操作PCに選ぶと、左の一覧へ自動で表示されます。ID・パスワードや本人設定コードは不要です。

途中でDesktopを終了しても、保存済みの登録から続けられます。「接続状況とサンプル」で登録・操作用途・実行PCの準備を確認してください。旧版からのPCは、管理者がプロジェクトのPC用途を確認して保存すると利用者の対応を準備します。

同じ人の別PCとして以前の依頼・承認を引き継ぐ場合だけ、Hub管理者が「既存の利用者・権限（詳細）」でこのPCと既存利用者を結び付けます。名前の一致だけで自動統合しません。

## 最初の仕事を確認する

依頼できるプロジェクトの新しいチャットで「接続状況とサンプル」→「サンプルの依頼を入力」を押すと、公開CSV（10・20・30）と依頼文を用意します。実行PCと共有内容を確認して「送信」してください。期待する結果は件数3・合計60と `moyai-sample-result.md` です。通常の仕事と同じ承認・実行・成果の経路を通ります。

既存の下書きや添付がある場合は上書きせず、新しいチャットを案内します。Readerは依頼できる担当者の結果を閲覧して確認できます。AI登録・実行フォルダー準備・PC応答は仕事成功と区別します。失敗した試行は自動で再投入しません。

同じWindows利用環境・登録PC・Hubでは、起動時と資格の期限後に自動で接続を確認します。端末の秘密鍵を別PCへコピーしないでください。共通接続ファイルに含まれるのはHub URLと公開CAだけです。

Hub管理者によるPC停止・失効、利用者の停止、対応先の変更が利用資格へ反映されます。Hubや端末の登録が変わった場合、以前の資格を別の接続先へ流用しません。Hub管理が許可された利用者のPCでは「Hubの管理画面を開く」から管理ブラウザーを開けます。

接続や参加申請に失敗した場合は、「PCの接続」→「接続の詳細・診断」で理由を確認します。同名の別PC登録がある場合は、管理者に既存登録を確認してもらってから「参加申請を再試行」を使います。

## プロジェクトで会話する

1. 左の一覧からHubのプロジェクトを選び、「新しいチャット」を押します。
2. 実行するPCが一つなら自動で選びます。複数ある場合は依頼先を選び、「メッセージ」に内容を入力して「送信」またはCtrl+Enterで依頼します。チャット名は内容から自動作成します。名前や開始期限を指定する場合は「追加設定」を開きます。
3. 左の会話一覧から、進行中の仕事や終了した結果を開きます。設定を開いて閉じても、元のHubプロジェクトへ戻ります。ローカルプロジェクトは同じ一覧から切り替えられます。
4. 確認が必要な操作は会話本文より上に表示します。判断権限がある場合は「あなたの承認を待っています」と表示されます。操作内容・コマンド・対象・許可した場合の影響を読んで、許可・拒否・停止を選びます。長い会話を読んでいるときは、上部に残る「承認内容と操作ボタンへ」から移動できます。操作種別や有効期限、元の診断情報は「承認の詳細・元のデータ」で確認できます。
   判断後は「この操作を許可しました」などの見出しにまとまります。元の操作内容は「詳細」を開いて確認してください。操作を許可したことと仕事の完了は別で、実行結果はその下に表示します。
5. 終了した仕事に会話の保存と継続する権限がある場合は、その会話の「メッセージ」から追加の依頼を送れます。元の仕事は終了状態のまま残り、履歴を引き継ぐ新しい仕事を作ります。

実行に使うAI、作業フォルダー、許される操作は実行PCの設定に従います。依頼文から設定を広げることはできません。選択していたPCが利用できなくなった場合は、入力を保持して別のPCの選択を求めます。入力中の依頼を別PCへ自動で振り替えることはありません。

受付結果が未確認の場合は「前回の依頼の受付を確認」を使います。保存済みの同じ依頼を照合し、新しい仕事として重ねて送りません。Desktop再起動後も同じHub・利用者で続けられます。別の利用者へ結び付け直したPCから以前の人の未確認依頼を再送しません。

開始期限の空欄は、投入操作から24時間です。期限は最初の送信前に保存し、再送や再接続で延長しません。子の仕事も元の期限を引き継ぎ、期限後は新しい実行や親の再開を始めません。既に開始済みの処理を打ち切る期限ではありません。

「実行を停止」は、その仕事の根と子の仕事全体へ取消を要求します。実行中の処理は、停止を確認するまで取消処理中のままです。画面を閉じること、接続解除、通信断は停止の確認になりません。

## 入力・会話・成果を共有する

「ファイルを添付」を開き、「ファイルを選択して添付」で入力を選ぶと、その時点の内容をHubへ保存します。1件8MiB、次の依頼に32件まで添付できます。実行先には写しを配置し、利用者の元ファイルを直接変更しません。同名の入力を選び直すと、アップロード成功後に添付を新しい内容へ置き換えます。

会話から共有された成果ファイルを確認できます。「名前を付けて保存」は保存先を選び、受け取った内容のハッシュを確認して保存します。「元の版と照合して取り込む」は、既存ファイルが成果の基準版と一致する場合だけ置き換えます。基準版がない、または既存の内容が変わっている場合は、別名で保存して確認してください。

同名の成果が複数回共有された場合は、「最新版」を先に表示します。「以前の版」を開くと旧版も保存・確認できます。最新版の内容が削除済みでも、旧版を最新版として扱いません。

会話と結果は本文を先に表示します。実行環境や操作の記録は見出しにまとめ、「記録の詳細」「結果の詳細」から識別情報や元データを開けます。ファイルのSHA-256は「ファイルの詳細」で確認できます。同じ仕事の更新中は開閉状態と選択した本文を保持し、利用者や仕事を切り替えたときは持ち越しません。

仕事が失敗した場合は、保存された失敗理由を「仕事を完了できませんでした」の下に表示します。途中までの回答があれば「中断までの回答」に残ります。AIへの接続失敗、認証、応答待ちの時間切れなどは、原因に応じた日本語の確認事項を表示します。接続失敗でホスト名を使っている場合は、その名前が現在のIPアドレスを指しているかも接続先の担当者に確認してください。実行PCの設定を変更できない場合は、そのPCの担当者にエラーを伝えてください。続けられる仕事では「続きの依頼へ」から入力欄へ移動できます。原因を解消してから、同じ会話で続きの依頼を送ってください。保存済みの結果は「結果の詳細」で確認できます。

生成するAIには、受け渡すスクリプトやコマンドを別のPCでも使える入力指定にし、正常・境界・不正入力で期待する結果を実装前に決めるよう案内しています。実装後は必要に応じて出力先を分けて実行し、結果・標準エラー・終了コードを確認します。検証で見つかった実装の問題を修正し、該当する確認をやり直します。実行方法・必要なファイル・実測した結果・未実施の確認は回答に含めます。関連する入力エラーでは、部分的な結果を成功として返さないことも確認対象です。これは生成時の指示であり、成果の保存や仕事の完了だけで品質検証の成功を保証するものではありません。

管理者が保存期間によって内容を削除したファイルは、名前と履歴を残して削除済みと表示します。削除済みの内容は保存・取り込みできません。入力を選び直すと、新しい内容として添付できます。

「お知らせ・要対応」から承認依頼、終了、担当引継ぎの対象を開けます。通知を開くと既読になり、仕事の現在の権限で操作します。現在の担当者またはプロジェクト管理者は、仕事の詳細で次の担当者を選べます。実行中の場合は安全に区切れるまで変更を保留し、適用後は新しい担当者の権限で続けます。

承認待ち中に担当交代を依頼すると、同じ操作の承認が再提示されます。交代が確定するまでは元の担当者またはプロジェクト管理者が判断してください。仕事が中断地点に達する前に完了した場合は、担当を交代せず終了します。

## このPCで仕事を実行する

依頼を確認・送信するだけのPCでは、以下の設定は不要です。

1. 初期画面で「チームの仕事をこのPCで実行する」を選び、AIの接続先とモデルを設定します。「AI設定を保存してPCの接続へ」を押すと、Hubへの接続画面が開きます。管理者から受け取った接続ファイルを読み込み、PCの参加承認を待ちます。実行用PCの設定には、利用者としてのログインは不要です。
2. 「moyAI Hub」→「PCの接続」の「このPCで仕事を実行」で「保存先と実行許可を設定」へ進みます。折り畳まれている場合は見出しを開いてください。「実行する操作の確認」を選び、「保存先フォルダーを選ぶ」で既存の親フォルダーを選びます。
3. 表示された保存先と権限を確認し、「この設定で実行を許可」を押します。標準の「承認を求める」では、確認が必要な操作を仕事の担当者が判断します。
   プロジェクトの割り当てがまだなら「このPCの実行設定は保存済みです」と、次にHub管理者へ依頼する内容を表示します。PC名を管理者へ伝え、プロジェクトの実行PCに割り当ててもらってください。保存先や実行許可をやり直す必要はありません。
4. Hub管理者がプロジェクトの実行PCに選ぶと、その保存先の下に作業フォルダーを自動で作成します。「作業フォルダーの準備中」から「作業フォルダー作成済み」へ進むことを確認してください。管理者はPCの初回設定より先に割り当てを保存することもできます。AIが実際に回答と成果を返せることは、サンプルの依頼で確認してください。

通常はRunnerを別に起動したり、ひな形や実行環境の識別名を入力したりする必要はありません。Desktopが実行機能を起動・再接続します。同じPCを複数プロジェクトや操作・実行の両方に使えます。標準ではこのPCのmoyAI実行を一つの共通枠にまとめ、同時利用数を1にします。

保存先と権限は一度確認すると保持します。同じプロジェクトでHubが許可したPCへの子の仕事の委任も、この設定の範囲で扱います。同じHub・端末資格・公開CAを検証したURL変更では保存済みの実行許可を保持します。別Hubや端末資格には以前の許可を流用しません。変更前に開いたフォルダー確認は接続先変更で無効になり、開き直しが必要です。設定を変更しても、作成済みの実行環境の権限を遡って変更するものではありません。

初回の実行許可が保存されなかった場合は、確認した保存先と失敗理由を画面に残します。理由を確認して同じ設定で再試行するか、保存先を選び直してください。保存されていない許可を、周期的な状態更新で許可済みとして扱うことはありません。保存済みの許可は再接続時に確認して復旧します。

「新しい仕事の受付を一時停止」は新しい受付を止め、「受付を再開」で戻します。実行中の仕事の停止は会話側で行います。Desktopを閉じたりHubとの画面の接続が切れたりしても、受け付けた仕事は続きます。Windowsの終了・サインアウト後まで同じプロセスが続くという意味ではありません。

「このPCで仕事を受け付ける時間」で、現在のWindows利用者がサインインしたときの自動起動を明示的に有効／解除できます。設定しない場合はmoyAIを開くと起動します。PCの電源断・サインアウト中の無人実行は対象外です。

「接続の詳細・診断」のHub診断は仕事の操作用接続を確認します。Hub経由のAIをこのPCで使う場合だけ追加のGateway診断を使ってください。Direct AIの確認は通常のAI設定で行います。

「停止を確認できない処理」がある場合は、確認する仕事・試行・世代を選び、外部システムへの影響と関連プロセスの停止を現地で確認してから、理由と確認欄を記入して記録します。別の処理を選ぶと確認欄はリセットされます。通信が切れたことだけを停止の根拠にしません。詳しい運用は [実行PCの設定と運用](runner-shared.md) を参照してください。

## PCの利用状況と通信

実行するPCの選択肢と「PCの利用状況」には、Hubで登録した現在のPC名を表示します。管理者が割り当てたPCは初回設定前から表示され、「このPCの初回設定待ち」なら表示されたPCで仕事の実行を許可します。「実行場所を準備中」や準備の失敗も区別して表示します。未設定のPCへは送信できません。

右側の「PCの利用状況」で共通枠の占有数を確認します。同じ枠を使う別プロジェクトの仕事も占有数へ含みますが、閲覧できない仕事の人名や件名は表示しません。環境は20件ずつ表示し、「ほかのPC」で次へ進みます。

実行PCと会話には、Hubが確認した実行機能の通信応答と最終応答時刻を表示します。15秒以上応答を確認できない場合は「PCの応答なし（状態不明）」になります。Hub再起動後も、新しい応答が届くまでは未確認です。別DesktopからHubの画面を更新しても、実行PCの応答時刻は更新しません。

この表示は処理の進捗や新規受付の保証ではありません。通信が不明でも仕事や占有枠を消さず、確認済みの結果を引き続き表示します。枠が空いているという記録だけで、実行の準備が整ったとは判断しません。
