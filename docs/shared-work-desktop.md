# DesktopのHubプロジェクト

Hubで操作を許可されたプロジェクトは、左側の通常の「プロジェクト」一覧に `Hub` 印付きで現れます。ほかのチャットと同じ入力欄へ目的を送ると、AIが許可されたPCを使って作業します。送信のたびに実行PCを設定したり、Hubで使うためにローカルプロジェクトを作ったりする必要はありません。

Hub会話・仕事・成果は、そのプロジェクトを閲覧できる利用者に共有されます。独立したローカルプロジェクトとプロジェクト外チャットはそのPCの会話として残り、Hubへ自動移管されません。

## 初回の接続

1. 初回画面の「チームに参加する」、または「moyAI Hub」→「PCの接続」から、管理者の `hub-config.moyai-join` を読み込みます。
2. このPC固有の鍵とWindowsユーザー名の参考情報で参加を申請します。Hub管理者がPCを確認・命名・承認すると接続します。同じWindowsユーザー名でも別PCは別登録です。
3. Hub管理者がプロジェクトの操作PCへ追加すると、左の一覧に表示されます。ID・パスワードや本人設定コードは不要です。

接続ファイルに入るのはHub URLと公開CAです。端末の秘密鍵を別PCへコピーしないでください。通常の再起動後も登録は保持します。保存済みHub接続がある間、AIのURLはHub管理となり、「設定」→「AIの接続」ではモデルを選べます。以前の手入力設定は保持されます。

依頼を送るだけの操作PCには、実行用フォルダー・ローカルAI・実行許可の設定は不要です。実行も行う場合は次節を設定します。準備状況はプロジェクトの「PCの利用状況」、通信失敗は「PCの接続」→「接続の詳細・診断」で確認できます。

## このPCで仕事を実行する

1. 初回画面では「チームの仕事をこのPCで実行する」を選び、接続ファイルを読み込んでPC参加の承認を受けます。AIはHubの標準モデルを使い、URLの手入力は不要です。
2. 参加承認後、「moyAI Hub」→「PCの接続」→「このPCで仕事を実行」の「1. このPCの実行許可」を設定します。「実行する操作の確認」を選び、「フォルダーの作成先を選ぶ」で実行用フォルダーを新しく作る場合の保存先を指定します。
3. 場所と権限を確認して「この設定で実行を許可」を押します。標準の「承認を求める」では必要な操作を仕事の担当者が判断します。
4. Hub管理者がこのPCをプロジェクトの実行PCへ割り当てます。PC側の許可と割当の順番はどちらが先でも構いません。未割当なら「このPCの実行設定は保存済みです」と表示します。
5. 「2. プロジェクトの作業フォルダー」の「作業フォルダーを選ぶ」から、AIが実際に読み書きする場所をプロジェクトごとに登録します。「1」の保存前は選択できません。途中まで作ったファイルがある既存フォルダーも使えます。PCごとに異なる場所で構いません。

RunnerはDesktopが自動で起動・再接続します。通常、手動起動やJSONの編集は不要です。同じPCを操作と実行の両方、複数プロジェクトで利用できます。標準ではこのPCのmoyAI実行を一つの共通枠にまとめます。

「1」の作成先は、新しくフォルダーを作る場合の保存先です。既存プロジェクトの作業場所を変えるときは、「2」の対象プロジェクトで作業フォルダーを選び直してください。

フォルダーが削除・移動された場合は、そのプロジェクトをこのPCで実行できない状態として表示します。以前の版で自動作成したフォルダーも同様です。「2」で現在の作業フォルダーを選び直すと、既存のファイルをそのまま使えます。なくなったフォルダーを自動で作り直すことはありません。ほかの準備済みプロジェクトは利用できます。

新しいプロジェクトの登録も含め、フォルダーの選択・変更はこのPCの仕事と起動中アプリがすべて停止してから行います。停止が必要な間は案内を表示し、選択ボタンを無効にします。

操作に失敗した場合は、次に操作し直すか接続先を変更するまでエラーを表示します。変更・離脱でファイルを自動移動・削除しません。

## 依頼・承認・成果確認

1. `Hub` 印のプロジェクトで「新しいチャット」を開き、通常の入力欄へ目的を書いて送信します。たとえば「WinAとWinBを用い、WinBをホストとしてFlaskのTODOアプリを作ってください」と依頼できます。
2. 必要なら「ファイルを添付」から入力を選びます。その時点の内容をHubへ保存し、実行先へ写しを渡します。元ファイルを直接変更しません。上限は1件8 MiB、次の依頼に32件です。
3. 別PCの操作も、依頼したPCの元の会話で承認します。実行PC・承認するPC・仕事・コマンド・作業フォルダーを確認し、「この操作を許可」「許可しない」「仕事を停止」を選びます。長い会話では「承認内容と操作ボタンへ」から移動できます。許可は表示された1回の操作に限り、実行の成功を意味しません。「許可しない」「仕事を停止」は依頼全体と子の仕事を停止し、次の指示を待ちます。
4. 結果と成果は同じ会話に表示します。「名前を付けて保存」で手元へ保存できます。「元の版と照合して取り込む」は保存先の内容が基準版と一致する場合だけ更新します。不一致や基準版がない場合は別名で保存してください。
5. 続きの依頼も同じ会話へ送ります。AIは許可されたPCと、そのPCに登録された作業場所・実行権限を使います。依頼文から権限を広げることはできません。

最初の動作確認では、新しい会話の通常の入力欄に「10・20・30の件数と合計を計算し、日本語で回答してください。結果を作業フォルダーの moyai-sample-result.md に保存して共有してください。ほかのファイルの変更や外部への接続は不要です」と入力して送信します。件数3・合計60と成果ファイルを確認してください。特定のPCを試す場合は、依頼文にそのPC名も書きます。

承認の15分期限が切れても依頼全体は終了せず、その操作の再確認を待ちます。依頼元の会話で「操作を再確認」を選び、新しく提示された内容へ回答してください。

Windowsでは承認待ちをバルーンで通知します。通知を見たらmoyAIの該当する会話を開いてください。通知自体では許可されません。AIからの通常の質問は会話の返答として届き、実行終了の通知から確認できます。Windows側の通知設定によって表示されない場合も、会話内の承認表示は利用できます。

実行中は同じ会話に、担当PCから届いた応答・操作・結果を表示します。「更新」はHubがその記録を受け取った時刻です。長い内容は一部を省略し、直近の記録を表示します。「結果待ち」はまだ操作結果が届いていない状態で、実行の成功を意味しません。承認が必要な仕事は「承認内容を確認」から具体的な操作を確認できます。仕事が終わると、回答と保存された実行記録から結果を確認できます。

同名成果の「最新版」と「以前の版」は分けて表示します。保存期間により内容が削除された成果は履歴だけを残し、保存・取込みはできません。実行記録やSHA-256は各詳細から確認できます。成果の保存成功だけでは、生成されたアプリの動作成功を意味しません。

## 停止と最新発言の編集

「停止」は現在の仕事と子の仕事へ停止を要求します。停止を確認するまでは取消処理中です。トレイへの格納や通信断だけでは停止済みになりません。仕事の後も利用するために起動したアプリは別に表示され、個別停止または会話全体の停止で終了できます。

通常チャットとHub会話では、**最新の送信済み発言だけ**を編集・再送できます。実行中なら先に停止し、Hub会話で保持中のアプリがある場合はその停止も確認してください。元の履歴は残り、修正後の依頼へ古い応答を混ぜません。すでに作ったファイルやDBを元に戻す操作ではありません。

編集では本文だけを変更し、元の画像や添付を送信時の内容で保持します。手元の元ファイルが変わったり削除されたりしても、保存済みの内容を使います。保存された画像が壊れている場合やHub側の添付が削除された場合は、添付を外して再送せず理由を表示します。添付を変更する場合は、新しい依頼として送ってください。

同じHub会話は他の操作PCにも見えます。会話の改名・削除も共有され、削除は対象の実行と保持アプリの停止確認後に完了します。端末上のファイルは削除しません。

## 受信PCの使用状況

別のPCから仕事を受けると、開いているチャットによらず「このPCは使用中」などの表示と停止入口が現れます。受信仕事が実行枠を使う間は、競合するローカルチャットの送信ができません。下書き、閲覧、チャット切替、このPCからの停止は使えます。実行・停止結果の確認後に送信制限を解除します。

操作権限がない仕事は「詳細を表示できない仕事」と表示します。実行専用PCに業務会話の閲覧権限を追加しなくても、使用状況の確認と、このPCからの停止は利用できます。Hubの画面更新と受信PCの状態反映は同時とは限りません。

「PCの利用状況」は準備状態・占有・Runnerの応答時刻を分けて表示します。「PCの応答なし（状態不明）」でも、仕事と資源を空きにはしません。別DesktopでHubの画面を更新するだけではRunnerの応答時刻は更新されません。

## 離脱・接続障害・運用

| 状況 | 操作と挙動 |
| --- | --- |
| プロジェクトから外れる | 操作PCはプロジェクトの「プロジェクトから離脱」、実行専用PCは実行設定の当該プロジェクトから離脱。このPCの両用途だけを解除し、他PC・Hubプロジェクト・端末ファイルは保持 |
| 再参加する | 新しい参加としてフォルダーを選び直す。同じフォルダーも指定可。旧仕事・下書き・承認・起動アプリは自動復元しない |
| 受付結果が不明 | 「前回の依頼の受付を確認」で保存済みの同じ要求を照合。新しい仕事として重複送信しない |
| 新規受付を一時停止 | 「新しい仕事の受付を一時停止」を使用。実行済み仕事の停止は会話から別に行う |
| Hubを交換・復旧できない | 「接続設定をリセット」で旧Hubの応答を待たず解除し、新しい接続ファイルで参加。履歴・成果・以前の手動AI設定は保持。新Hubの実行許可は再確認 |
| 停止を確認できない処理 | 対象の仕事・試行・世代を選び、関連processと外部への影響を現地確認して回復操作へ進む。通信断だけを停止の証拠にしない |

Hub停止時に手入力のAIへ自動で切り替わることはありません。AI接続エラーでホスト名を使っている場合は名前解決も確認してください。確認済み結果と途中の回答は保持し、原因解消後に同じ会話で追加依頼できます。

Desktopの×によるトレイ格納、クラッシュや画面接続断では受け付けた仕事は独立Runnerで続きます。実行PCのメニューまたはトレイの「終了」は、接続中Runnerの仕事・保持アプリを正常停止し、Runnerの実プロセス終了を待ってDesktopも終了します。Hub本体は別に管理します。「このPCで仕事を受け付ける時間」で現在のWindows利用者のサインイン時自動起動を設定できます。Windowsサインアウト・電源断中の実行は対象外です。詳細なCLI・保守・回復は [共有Runner](runner-shared.md) を参照してください。

依頼の承認・追加指示・発言編集・通常停止は、送信した操作PCから行います。別のPCから共有会話を閲覧できても操作を代行できません。別の操作PCは自分の新しい会話を開始します。担当交代の画面や操作はありません。会話名の変更は従来どおり共有権限で行えます。履歴の削除も、実行とアプリの停止確認後は共有権限で行えます。実行停止が必要な会話の削除は依頼元PCから行います。

管理上の取消や停止状態の確定と、実行PCの緊急停止は別の操作として利用できます。
