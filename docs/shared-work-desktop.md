# Desktopの共有仕事

Desktopの「共有仕事」から、Hubに所属するプロジェクトの仕事と実行環境を確認できます。初期設定の開始画面からも開けるため、このPCのモデル設定やローカルプロジェクト作成は必要ありません。ローカル作業の初期設定は別に保持されます。

1. Hub管理者から受け取った共通設定を読み込み、端末の参加承認を待ちます。共通設定に含まれるのはHub URLと公開CA信頼です。
2. 承認後、Hub利用者のアカウントでログインします。端末登録と、人のプロジェクト所属・操作権限は別です。
3. 所属プロジェクトを選び、実行環境の空き・利用者・仕事の状態を確認します。所属外の仕事は人名や件名を出さず、使用件数を表示します。同じ共通枠を使う実行環境では占有数も共有されます。
4. 投入できるプロジェクトでは、実行環境・件名・依頼内容を指定します。作業フォルダ、モデル、アクセス権限は実行環境側の設定を使います。受付結果が未確認の場合は「前回の依頼の受付を確認」で保存済みの依頼を照合します。ログアウトやDesktop再起動後も、同じHubの同じ利用者で再ログインすると照合できます。
5. 一覧から仕事の詳細・結果を確認し、権限がある仕事を取り消せます。取消はその仕事の根と子の仕事全体へ適用され、実行中の処理は停止確認まで取消処理中になります。
6. 実行の承認が必要な仕事は詳細に操作内容を表示します。判断権限のある担当者またはプロジェクト管理者が、許可・拒否・停止を選択します。
7. 「お知らせ・要対応」から、承認依頼、終了、担当引継ぎの対象を開けます。開いた通知を既読にし、仕事の現在の権限で操作します。通知はアプリ内に表示します。

仕事の投入と追加依頼では開始期限を指定できます。空欄は投入操作から24時間です。期限は最初の送信前に保存し、接続失敗後の再送や再ログインで延長しません。子の仕事も元の仕事の期限を引き継ぎ、期限後は新しい実行や親の再開を始めません。既に開始済みの処理を打ち切る期限ではありません。停止未確認の処理を期限だけで終了扱いにすることもありません。

端末の参加に失敗した場合は、この画面に理由を表示します。同じ端末名の登録が残っている場合は、Hub管理者に既存登録の名前変更または不要登録の削除を依頼してから「再接続・承認状況を確認」で再試行します。

## 入力・会話・成果の受け渡し

投入前に「ファイルを選択して添付」で入力を選ぶと、その時点の内容をHubへ保存します。1件8MiB、次の依頼に32件まで添付できます。実行領域へは入力の写しを配置し、利用者の元ファイルをそのまま変更しません。

同じ名前の入力を選び直すと、アップロード成功後に添付を新しい内容へ置き換えて通知します。32件に達していても同名の置換はできます。保持期限で内容が削除されたファイルも、選び直すことで新しい入力として添付できます。

仕事の詳細から共有された会話と成果ファイルを確認できます。「名前を付けて保存」は保存先を選び、Hubから受け取った内容のハッシュを確認して保存します。「元の版と照合して取り込む」は、既存ファイルが成果の基準版と一致する場合にだけ置き換えます。基準版がない、または内容が変更されている場合は既存ファイルを保持するため、別名で保存して差分を確認してください。

会話と結果は本文を先に表示し、操作の識別情報や元データは「記録の詳細」「結果の詳細」から開けます。同じ仕事・ページの更新中は開閉状態と選択した本文を保持し、利用者や仕事を切り替えたときは持ち越しません。

終了した仕事に会話の保存と継続する権限がある場合、「追加の依頼」から新しい仕事を作れます。元の仕事は終了状態で残ります。未確認の追加依頼も同じ受付IDを保存し、再ログイン・再起動後に照合します。

管理者が保持期限によって内容を削除したファイルは、名前と履歴を残して削除済みと表示します。内容を削除したファイルの保存・取り込みはできません。

現在の担当者またはプロジェクト管理者は、仕事の詳細で次の担当者を選べます。実行中の試行がある場合は安全に区切れるまで変更を保留し、適用後は新しい担当者の権限で続けます。

## このPCで仕事を受け付ける

「このPCで仕事を受け付ける」は、ほかの端末から依頼された仕事をこのPCで実行するための設定です。仕事を依頼・確認するだけなら設定は不要です。このWindows利用者のRunnerを操作し、Hub利用者のログアウトでは受付や実行は停止しません。

1. 端末のHub参加を完了します。このPCには、実行に使うAIの設定も必要です。
2. 「このPCの状態を確認」を押します。Runnerが起動していなければ「実行用アプリ（Runner）を起動」し、状態を確認します。
3. 「作業フォルダのひな形」に名前を付けます。実行の権限は「必要な操作を確認（標準）」が選択されています。内部の識別名は自動で用意するため、通常は入力不要です。
4. 「保存先フォルダを選んで確認」で、このPC上の既存フォルダを選択します。表示された保存先・権限・子の仕事の依頼先を確認して「このひな形をHubに公開」を押します。
5. Hub管理者が「利用者と仕事の設定」で公開されたひな形を選び、プロジェクトの実行環境を追加します。公開だけでは仕事の実行は始まりません。

標準では、このPCのmoyAI実行を一つの共通枠にまとめます。「追加設定」には、内部の識別名、子の仕事を任せる環境、初回公開時の資源分離をまとめています。分離はソフトウェア・領域・外部への効果が独立していると端末の管理者が確認した場合に使います。業務の依頼内容から任意の保存先を指定することはできません。

受付中は「新しい仕事の受付を止める」、停止中は「仕事の受付を再開」を使います。「受付・自動起動・作成済みフォルダの管理」には、実行完了を待つ停止、保守予定、Windowsログイン時の自動起動、登録済み環境への手動作成をまとめています。実行状態が不明な試行は、対象の外部効果と関連プロセスの停止を現地で確認してから記録します。画面や通信が閉じたことだけで停止確認を行わないでください。

親フォルダの確認は、選択時のHub・端末・証明書に結び付けます。適用前に接続設定が変わった場合はフォルダを選び直してください。

公開中のひな形は「作成・変更するひな形」で選ぶと名前・権限・子の依頼先を再利用できます。保存先を選び直して確認し、同じ識別名で更新します。フォルダ確認後に入力を変更した場合も、再確認してから公開します。「新しいひな形を作る」を選ぶと新規作成になり、既存のひな形を上書きしません。公開をやめても作成済みのフォルダは残ります。別の画面が先に変更した場合は、受付状況を更新してから内容を確認し直してください。

画面を閉じても、Hub利用者からログアウトしても、HubとRunnerが所有する仕事は続きます。ログアウトすると表示とキャッシュを消去します。人のセッションはDesktopプロセスのメモリだけに保持するため、Desktopを再起動した場合や端末接続を解除した場合は再ログインします。ネットワーク障害時の結果確認には更新・再接続を使ってください。

仕事は50件、実行環境は20件ずつ表示します。「以前の仕事」「次の実行環境」で次ページへ進み、「最新の仕事・環境へ」で先頭へ戻ります。画面上部の「Hubの情報取得」はDesktopが情報を取得した時刻です。

実行環境・仕事一覧・詳細には、Hubが確認したRunnerの共有制御通信と最終応答時刻を表示します。15秒以上応答を確認できない場合や、Hub再起動後にまだ応答がない場合は「状態不明」と表示します。これは処理の進捗・正常動作・新規受付の保証ではありません。通信が不明でも仕事や占有枠を消さず、完了済みの結果を引き続き表示します。空き枠の記録だけで実行準備が整ったとは判断しません。

## 実装と検証

- `src/device_network/shared_work.rs` が人のtoken、認証世代、所属、選択対象、ページ、取得済み状態を所有します。端末の既存mTLS clientと接続leaseを使用し、資格情報をWebViewへ返しません。`shared_work/receipts.rs` が未確認の依頼とrequest IDを既存のprivate端末設定ディレクトリの`shared-submissions.json`へ送信前に保存します。最大32件・2MiBで、破損や保存不能時は既存記録を保持し、新規投入を止めます。認証tokenは保存しません。
- `src/desktop/state.rs` とTauri commandsが、初期設定を完了させずに共有入口へ遷移します。
- `ui/desktop-web/src/shared_work_*.ts` は入力draftと表示を扱います。取得結果は世代と順序を確認し、logout中は即時に旧内容を隠します。アプリ共通の更新周期を使い、入力中のフォームを接続したまま保持します。
- actual Tauriシナリオ `settings.shared-work` は、設定なしの起動、native共通設定選択、実Hubの参加承認、2人の利用者の所属分離、占有秘匿、投入・詳細・取消・ログアウト、具体的な操作承認の確認・許可・決定済み表示を扱います。実solver実行と物理別PCの試験は別の検証範囲です。
- `settings.shared-work-continuation` は、一つのHubと実Runnerを維持し、Desktop Aの終了から、別の端末登録・設定のないDesktop Bによる操作承認、成果保存、担当交代、Hubの会話を使う追加依頼までを扱います。同一Windows内の分離した端末設定であり、物理別PCや外部solverの受入とは区別します。
