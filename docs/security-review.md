# セキュリティレビュー支援

moyAIは、変更や外部操作を行う際の確認を共通指示、組み込みSkill、実行記録の照合で支援します。[OWASPの公開資料](https://owasp.org/www-project-application-security-verification-standard/)を参考にした独自実装です。OWASPのSkill本文やASVSデータを同梱した製品ではありません。

## 使い方

Mainエージェントは、変更を始める前に `skill` で `moyai-security-review` を読みます。利用者によるSkillファイルの配置や追加設定は不要です。この名前は組み込み用に予約され、同名のworkspace Skillでは置き換えられません。

最後の変更後に、対象の読み取りや許可されたテストなどを行い、`security_review` に次の情報を渡します。

- `summary`: 確認した対象と結論。
- `findings`: 残っている問題。空欄でも安全の証明にはなりません。
- `limitations`: 未確認の範囲、実行できなかった検査、判断の限界。
- `check_tool_call_ids`: 現在のターンで実行した確認操作のID。

確認操作のIDが本文に表示されない場合は、既存の `read_history` から取得します。

1. `query` に検査コマンドの特徴的な文字列、または `shell` などのTool名を渡します。検索はJSONのキー名ではなく文字列の値が対象で、正規表現ではなく大文字・小文字を区別した部分一致です。`tool_call` で呼出し記録も探せます。必要な記録が見つかるか検索が終わるまで、返された `next_after` を次の `after` に渡します。
2. 実際に行った操作に対応する `matches[]` を選び、その `item_id` を `read_history` の `item_id` に渡します。返された `text` はJSONとして読みます。途中までの場合は `next` で続きを取得し、記録の `call_id` を変更せずに `check_tool_call_ids` へ入れます。履歴の `item_id` と操作の `call_id` は別のIDです。
3. 同じコマンドでも、以前のターンの結果を流用しません。呼出し記録だけで成功と判断せず、実際の結果を区別します。操作を特定できない場合はIDを作らず、根拠を確認できなかったことを `limitations` に残します。

検査の実行を妨げる権限や利用者の禁止事項を、この手順で回避することはできません。スキャナの自動導入や外部システムへの無許可の検査も行いません。追加の変更を行った場合は、その結果を確認してレビューを記録し直します。専用の読み取りToolだけを使う通常の回答には、この追加工程を要求しません。

## Harnessが確認すること

IDは同じsession・turnの正本履歴へ照合します。canonical Tool IDと、一意に解決できるprovider Tool IDを受け付けます。存在しないID、別ターン、未完了の操作、重複、レビュー自身の参照は拒否します。失敗した検査の結果は失敗のまま記録します。

providerが同じIDを複数の操作に使った場合、推測で一つを選びません。上記の手順でTool名やコマンドから対象の記録を特定し、canonical `call_id` を使います。`read_history` の公開記録にはproviderのIDや内部metadataを含めないため、それらを検索できるとは限りません。

既存のTool分類とFileChangeから変更境界を求め、レビュー後の追加操作を検出します。Compactionの要約で確認状態を上書きせず、保持された正本を使います。変更対象は安定した履歴IDで結び、共有環境への復元で通し番号が変わっても照合します。shellは変更を起こし得る操作として扱います。事前の権限拒否を変更へ読み替えず、失敗や中断で副作用を否定できない操作は保守的に対象とします。

ターン終了時には、レビュー未実施、変更後の再確認なし、確認操作の根拠なし、残る問題や未確認範囲を、既存の履歴feedbackへ表示します。レビューを省略しただけで追加のモデル呼出しを繰り返す仕組みはありません。

## 保証の範囲

これはレビューを支援し、未実施や古い記録を検出する機能です。レビュー実施の強制、安全認証、脆弱性の不存在の保証ではありません。`Completed` は作業ターンの終了を表します。安全確認済みを意味せず、最終文中の不適切な安全宣言を自動で抑止するものでもありません。

Harnessは確認操作の実在、結果、順序を照合します。操作が適切な検査だったか、対象を十分に確認したかという意味上の判断には、モデルと利用者の確認が必要です。継続中のプロセス、別プロセス、Toolを通さない変更は、履歴順序だけでは検出できません。

利用者の追加指示やSkillを理由に、moyAIのpermission、Guardian、OS sandboxの権限は拡大しません。Side Chatには変更用Toolやこの工程を追加しません。
