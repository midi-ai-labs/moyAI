# moyAI v2.0.1

## 日本語

v2.0.1は、Desktopの設定・実行状態を整理し、provider接続、長時間task、再起動後の回復を強化する大型更新です。session単位のtool-less Side Chat、global / session設定workflow、統一provider profileを追加しました。

### 主な変更

- メインtaskとは別modelを使える、text-only・tool-lessなSide Chatを追加しました。provider設定、canonical会話履歴、未送信draftはowning session単位で永続化されます。実行とStopはmain taskから分離されたowner session / Side Chat ID / request generationでfenceされ、settleした結果はcanonical terminalとして保存されます。
- fullscreen Initial Setup、user-wideなPreferences、root-session専用のSession Settingsを完成させました。TOML Importは任意の`.toml` filenameを受理し、Finishまではsource fileや現行configを変更しません。
- catalog discoveryとgeneration transportの組合せを4つのtyped `provider_profile`へ統合し、同じprofile契約をDesktop、TUI、CLI、session、Side Chatで共有しました。optional `api_key_env`はkey値ではなくenvironment variable名を保存しますが、利用できる認証入力はsurfaceごとに異なります。
- exact Stopは表示時のworkspace / root session / run generation-or-epoch / turn admissionを検証し、stale actionがreplacement runを停止しません。再起動後はsettled canonical history / terminalを復元し、同一sessionの次turnを新しいadmission revisionで開始できます。
- Initial Setup、Settings、Side Chat、実行中taskのactivity表示、focus、async responseの所有境界を整理し、stale responseが別sessionや新しいdraftを変更しないようにしました。
- temperature / top-p / top-k / penalty / seed、thinking body、reasoning effort / summary、stop sequence、output length、provider固有bodyはprovider host側の設定を使用します。`request_timeout_ms`は最初のPOST attemptからsuccessful response headerまでのabsolute deadlineと、その後のdecoded SSE event間のrolling inactivity timeoutを兼ねます。streamが進捗している限り総所要時間だけでは停止しませんが、固定stream limitとcancelは引き続き適用されます。
- semantic compactionは、最古側のcomplete semantic-unit prefixだけをboundedに要約します。typed `context_length_exceeded`、またはeffective input limit到達時にcompletion全体がreasoning tokenで本文が空だった場合に限り、strictly shorterなsemantic-unit prefixで一度だけ再試行します。成功requestに含まれたunitだけをreplacement lineageへ記録します。
- actual Tauri Desktopを操作する再利用可能なE2E harnessを追加し、設定、Stop、permission、Desktop restart後のprovider-turn continuity / history recovery、long-context compaction、case5_2を共通driverとevidence contractで検証できるようにしました。

### 更新時の注意

- このreleaseにはforward migration V54〜V60が含まれます。既存dataは初回起動時に更新されるため、重要なAppDataは更新前にbackupしてください。
- 新しいcanonical provider設定は`provider_profile`です。旧`provider_metadata_mode` / `provider_api_mode`と対応するenvironment variableはcompatibility inputとしてprofileへ正規化され、新しい保存では出力されません。同一input layerでcanonical / legacy指定が矛盾する場合はconfig errorになります。
- 旧`stream_idle_timeout_ms`と`MOYAI_STREAM_IDLE_TIMEOUT_MS`は`request_timeout_ms`への移行入力としてだけ受理されます。同一input layerで新旧を異なる値にするとconfig errorになります。
- `context_window`はmoyAI内のinput accountingとcompaction budgetだけを制御します。providerのmodel loadやcontext sizeは変更しません。
- 旧configに残るtemperature、reasoning、`max_output_tokens`、stop sequence、provider固有body等はgenerationへ送信されません。必要な値はLM Studio、oMLX、その他のprovider host側で設定してください。
- Side Chatはmain providerのAPI keyやcustom headerを継承しません。現行のSide Chat provider設定は認証不要のendpointを対象とします。
- provider failure後に別generation endpointへ自動fallbackしません。同一endpointへのpre-response retryは`max_retries`の範囲で行いますが、別endpointへのfallbackでgenerationやtool callを重複させないための意図的な動作です。

## English

v2.0.1 is a major Desktop and runtime update focused on coherent settings ownership, provider connections, long-running tasks, and restart recovery. It adds a durable session-scoped tool-less Side Chat, complete global and per-session settings workflows, and unified provider profiles.

### Highlights

- Adds a text-only, tool-less Side Chat that can use a model separate from the main task. Its provider settings, canonical history, and unsent draft are persisted per owning session. Execution and Stop are isolated from the main task and fenced by owner session, Side Chat ID, and request generation; settled outcomes are stored as canonical terminals.
- Completes the fullscreen Initial Setup, user-wide Preferences, and root-session-only Session Settings workflows. TOML Import accepts any `.toml` filename and remains read-only until Finish.
- Unifies catalog-discovery and generation-transport pairings under four typed `provider_profile` values shared across Desktop, TUI, CLI, sessions, and Side Chat. Optional `api_key_env` stores an environment-variable name rather than the key value, while available authentication inputs remain surface-specific.
- Exact Stop validates the displayed workspace, root session, run generation or epoch, and turn admission so a stale action cannot stop a replacement run. After restart, settled canonical history and terminals are restored, and the next turn in the same session starts with a new admission revision.
- Consolidates ownership for Initial Setup, Settings, Side Chat, task activity, focus, and asynchronous responses so stale results cannot mutate another session or a newer draft.
- Leaves temperature, top-p, top-k, penalties, seed, thinking body, reasoning effort and summary, stop sequences, output length, and provider-specific body settings to the provider host. `request_timeout_ms` is one absolute deadline from the first POST attempt through a successful response header, then a rolling decoded-SSE inactivity timeout. A progressing stream has no client-side total-duration cutoff, while fixed stream limits and cancellation still apply.
- Bounds semantic compaction to an oldest complete semantic-unit prefix. It retries once with a strictly shorter aligned prefix only for typed `context_length_exceeded`, or when the effective input limit is reached and the completion is empty with all completion tokens reported as reasoning tokens. Only units included in the successful request enter replacement lineage.
- Adds a reusable actual-Tauri Desktop E2E harness with shared drivers and evidence contracts for settings, Stop, permissions, provider-turn continuity and history recovery after Desktop restart, long-context compaction, and case5_2.

### Upgrade notes

- This release includes forward migrations V54 through V60. Existing data is upgraded on first startup; back up important AppData before upgrading.
- `provider_profile` is the new canonical provider setting. Legacy `provider_metadata_mode` / `provider_api_mode` values and their environment-variable forms are normalized as compatibility input but are not written by new saves. Conflicting canonical and legacy values in the same input layer are rejected.
- Legacy `stream_idle_timeout_ms` and `MOYAI_STREAM_IDLE_TIMEOUT_MS` are accepted only as migration input for `request_timeout_ms`. Different old and new values in the same input layer are rejected.
- `context_window` controls only moyAI-local input accounting and compaction. It does not load or reconfigure the provider model.
- Legacy temperature, reasoning, `max_output_tokens`, stop-sequence, and provider-specific body settings are no longer sent on generation requests. Configure them in LM Studio, oMLX, or the selected provider host.
- Side Chat does not inherit the main provider's API-key reference or custom headers. Its current provider workflow targets unauthenticated endpoints.
- moyAI does not automatically fall back to another generation endpoint after failure. Pre-response retries to the same endpoint remain bounded by `max_retries`, but cross-endpoint fallback is avoided to prevent duplicate generations or tool calls.
