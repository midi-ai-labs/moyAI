# moyAI v2.1.1

## 日本語

v2.1.1はv2系の最終リリースです。v2.0.1で導入したDesktop Settingsとtool-less Side Chatを、Main / Side Chatそれぞれの追加システムプロンプト、ownerに紐づくcontext・引用・復元、明確な設定区分へ拡張しました。AutoReview Guardian、Windows process admission、MCP / provider / secret境界もfail closedに強化しています。

### 主な変更

- Main用の`model.system_prompt`とSide Chat用の`side_chat.system_prompt`を独立したglobal設定として追加しました。どちらもTOML Import / SaveとDesktopから設定でき、moyAI組み込みpromptを置換せず、その後ろへ最大16,384 Unicode文字の追加指示として連結します。
- Side Chatは作成時にprovider、model、追加system prompt、timeout、retry、context budgetをowning session専用snapshotへ固定します。ペインを隠す、sessionを移動する、windowを閉じる、appを再起動する操作では履歴・draft・snapshotを保持し、明示的に閉じた場合だけ削除します。
- Settingsを**Global Settings**（Main Chat Settings / Side Chat Settings）、**Session-scoped Settings**（Session Overrides）、**Desktop Preferences**へ再編しました。user-wide TOML、root Main sessionのoverride、window / UI stateの保存ownerを画面上でも区別できます。
- Side Chatへの質問はselected owner sessionのbounded canonical historyとappend fenceを送信直前にcaptureします。引用はstable history identityとsource revisionへ束縛され、untrusted textは構造delimiterを偽装できない形でencodeされます。scope、as-of position、truncationをUIへ表示し、Main composer、Main run、workspace access、Side Chat Stopのownerを分離します。
- session再選択と遅いtitle refreshをstable session IDへ収束させ、sidebar、header、terminal status、active turnの表示ずれを防ぎました。実行中activity、attention-first progress、scroll / focus / IME、reduced motion、About表示も同じstate ownerへ整理しました。
- AutoReview Guardianはturn開始時にcaptureした`ProviderTarget`とcanonical API modeから、現行4種類のprovider profileそれぞれにexactなtool-less Responses / Chat Completions requestを構築します。OpenAI-compatible endpoint（oMLXを含む）を利用でき、未知wireや不整合はprovider接触前にfail closedし、human approvalへ暗黙fallbackしません。
- Windowsのshell / formatter executableをcanonical absolute pathとstable handle identityへ固定し、workspace shadowや置換された候補をspawn前に拒否します。Everyone-writeなsandbox candidateのACL適用・検証失敗、dynamic / indirect PowerShell、cross-origin MCP redirectも副作用前にfail closedします。
- providerのraw / malformed responseはprivate diagnosticへ閉じ、会話履歴、export、Desktop / TUIにはsafe public failureだけを残します。credential非投影、bounded Skill catalog、terminal-derived session usageのmissing / partial / complete区分も追加しました。
- actual Tauri E2EをSide Chat session / quote、Settings、session navigation、Guardian transport、parallel Main / Side executionまで拡張し、長いcase5_2には同じowner sessionへ問い合わせる独立Stage 5を追加しました。

### 更新時の注意

- このreleaseにはforward migration V61が含まれます。既存dataは初回起動時に更新されるため、重要なAppDataは更新前にbackupしてください。
- V61より前に作成済みのSide Chatには空の追加system prompt snapshotが設定されます。globalな`side_chat.system_prompt`を変更しても既存Side Chatは変化しません。新しい値を使うには、そのSide Chatを確認画面から明示的に閉じて作り直してください。
- Mainの追加system prompt変更はApply後にadmitされるturnから反映されます。組み込みpromptとdefault profile promptは常に先に維持されます。
- `[side_chat]`は`[model]`を継承しない独立したglobal sectionです。default値が同じでも、provider、model、prompt、timeout、retry、context budgetを別々に保存します。
- AutoReviewは承認結果をhuman reviewへsilent fallbackしません。選択したprovider profile / endpoint / modelが利用できない場合は明示的な失敗として扱います。
- v2.1.1はv2系の最終リリースです。

## English

v2.1.1 is the final release in the v2 line. It extends the Desktop Settings and tool-less Side Chat introduced in v2.0.1 with independent Main and Side Chat system prompts, owner-bound context, quotes and recovery, and clearer settings ownership. It also strengthens AutoReview Guardian, Windows process admission, MCP, provider diagnostics, and secret boundaries with fail-closed behavior.

### Highlights

- Adds independent global `model.system_prompt` and `side_chat.system_prompt` settings. Both can be configured through TOML Import / Save and Desktop, preserve the built-in moyAI prompt, and append up to 16,384 Unicode characters of additional instructions.
- Snapshots the Side Chat provider, model, additional system prompt, timeout, retry policy, and context budget for the owning session when a Side Chat is created. Hiding the pane, switching sessions, closing the window, or restarting the app preserves its history, draft, and snapshot; only an explicit confirmed close deletes it.
- Reorganizes Settings into **Global Settings** (Main Chat Settings / Side Chat Settings), **Session-scoped Settings** (Session Overrides), and **Desktop Preferences**, making the owners of user-wide TOML, root Main-session overrides, and window/UI state explicit.
- Captures the selected owner session's bounded canonical history and append fence immediately before a Side Chat request. Quotes are bound to stable history identity and source revision, and untrusted text is encoded so it cannot forge structural delimiters. The UI exposes scope, as-of position, and truncation while keeping the Main composer, Main run, workspace access, and Side Chat Stop under separate owners.
- Converges session reselection and delayed title refresh on stable session IDs so the sidebar, header, terminal status, and active turn cannot drift apart. Running activity, attention-first progress, scroll/focus/IME ownership, reduced motion, and About presentation are also consolidated.
- Builds exact tool-less Responses or Chat Completions AutoReview Guardian requests for every current provider profile from the turn-captured `ProviderTarget` and canonical API mode. OpenAI-compatible endpoints, including oMLX, are supported; unknown or inconsistent wires fail before provider contact and never silently fall back to human approval.
- Pins Windows shell and formatter executables to canonical absolute paths and stable handle identities, rejecting workspace shadows or replaced candidates before spawn. ACL application/verification failures on Everyone-writable sandbox candidates, dynamic or indirect PowerShell, and cross-origin MCP redirects also fail before effects.
- Keeps raw or malformed provider responses in private diagnostics and exposes only safe public failures in history, export, Desktop, and TUI. Credential-safe projection, a bounded model-visible Skill catalog, and terminal-derived missing/partial/complete session usage are included.
- Extends actual-Tauri E2E coverage across Side Chat sessions and quotes, Settings, session navigation, Guardian transport, and parallel Main/Side execution. The long case5_2 scenario now has a separate Stage 5 that queries the same owner session through Side Chat.

### Upgrade notes

- This release adds forward migration V61. Existing data is upgraded on first startup; back up important AppData before upgrading.
- Side Chats created before V61 receive an empty additional-system-prompt snapshot. Updating global `side_chat.system_prompt` does not mutate an existing Side Chat. Explicitly close it through the confirmation flow and create it again to capture the new value.
- Main system-prompt changes affect turns admitted after Apply. The built-in system and default-profile prompts always remain first.
- `[side_chat]` is an independent global section and does not inherit `[model]`, even when their defaults match. Its provider, model, prompt, timeout, retry, and context-budget values are persisted separately.
- AutoReview never silently falls back to human review. An unavailable or incompatible selected provider profile, endpoint, or model is reported as an explicit failure.
- v2.1.1 is the final release in the v2 line.
