# moyAI v3.0.0

## LYNX 暫定ビルド

2026-09-08。別のWindows x64端末でDesktopを確認するための非公開の暫定ビルドです。正式リリースではありません。配布物のmanifestに実際のsource commitとbuild identityを記録します。

- Desktopの配色・余白・情報の強弱をLYNXとして見直しました。
- moyAI Hubの共通設定から自動参加申請し、Hub管理者が接続端末一覧で許可すると自動接続する経路を実装しています。名前・参加コードの入力は不要です。受入端末の受付ON、依頼元の利用先ON、端末の鍵生成・相互TLS・証明書更新、Hubの方向付き許可、モデル割当、許可された再委任と親タスクからの停止を扱います。Hubの端末「停止」は可逆な新規利用停止で、恒久失効・実行中の仕事の停止とは区別します。HubアプリはこのDesktop配布物に含みません。
- 受入側の対話承認、承認待ちの表示、段階別の接続診断、任意の固定IPv4・ポート、証明書更新をまたぐ通信の継続、Hub再起動後の委任関係の復旧を追加しています。未確認の仕事を自動で再実行せず、終了が確認できない停止は未確認として扱います。
- 明示した版付き入力の受渡しと、終了した仕事が記録した成果物の確認・Windowsでの新規フォルダへの書き出しを追加しています。元のプロジェクトへの自動適用やフォルダ全体の同期ではありません。
- 主メニューを「MCP履歴」に変更しました。「MCP指示」「MCP実行」の一覧・詳細・保存済みの結果やエラーを確認し、Markdownで保存できます。受付OFFや再起動後も保存済み履歴を参照できます。対応版Hubからも端末を選んで履歴を取得・保存できます。Hubと各Desktopの両方を更新してください。詳細は [MCP履歴](docs/mcp-history-guide.md) を参照してください。
- 保存済みの手動配信profileがある場合は、履歴画面の「旧配信設定の管理」から管理できます。URL・トークンによる接続、読み取り6種と明示的なagent modeのProject/tempは互換機能として残ります。手動agent profileは受入側のGlobal Main Directモデルを使い、Hub管理経路の自動TLS・モデル割当・再委任とは別です。詳細は [MCP配信](docs/design/mcp-publish-foundation.md) と [複数端末への委任](docs/design/remote-agent-delegation.md) を参照してください。
- MCP画面の選択欄と、ウィンドウ復帰後に配信操作が更新されない不具合を修正しました。

## 別端末での起動

依頼元・受入側の両方で今回のビルドを使ってください。ZIPをフォルダーごと展開し、`bin/moyai-desktop.exe`を起動します。`ui/desktop-web/dist/`や`logo/`を含む配置を維持してください。RustやNode.jsの開発環境は不要です。WindowsのWebView2 RuntimeとMicrosoft Visual C++ x64ランタイムが必要です。これらのインストーラーはZIPに含みません。

Hubで接続する場合は、Hub管理者から共通設定を受け取り、「moyAI Hub」→「端末連携」で読み込みます。自動申請後、Hubの「接続端末」で管理者が許可すると、Desktopが証明書取得・接続まで自動で進みます。初回設定では「Hubの共通設定で始める」を使え、先にDirectモデルを登録する必要はありません。受入側でProject/temp・実行権限・モデルを確認して受付をONにし、Hubの許可を設定したうえで、依頼元の一覧から利用先をONにします。正確な操作手順は [Hubを使って端末を接続する](docs/hub-device-network-guide.md) を参照してください。

Hubを使わない直接接続も維持します。その場合は接続先LLMサーバーのURLとモデルを設定してください。別のPCのモデルには到達できるIPアドレスを指定します。`127.0.0.1`はDesktopを起動した端末自身です。モデルをホストする端末と、委任された作業を実行する端末は同じとは限りません。

同梱の`moyai.exe`はCLI / TUI用、`moyai-cleanup.exe`はmoyAIの保存データを初期化する保守用です。通常のDesktop起動には使いません。

## 確認範囲

今回の実装ソースではRust全体試験とDesktop frontend試験が合格しています。MCP履歴の両方向の表示・Markdown保存・再起動後の保持、Hubからの実行履歴取得・保存・切断後の取得済み表示は、Windowsの実GUIで確認しました。追加した承認・診断・成果物操作等の未確認操作、現在のソースでの実モデルによる往復の再確認、物理別Windows・3台再委任の受入は残っています。物理WinBでのCPU調査結果未取得は、履歴機能の追加だけで解消したものではありません。最終ソースと配布物自体の検証結果は、この暫定ビルドに対応するRESULTSとmanifestを参照してください。

以前の段階では、同一Windows上の実Hub/Desktop画面と分離した送受信runtimeで、参加・受付・利用先選択、実oMLXのCPU調査往復と個別停止を確認しています。この実績を今回追加した操作や配布物の検証完了へ流用しません。

## 主な制限

- 成果物と入力はUTF-8最大8件・各64 KiB・合計256 KiBで、JSON化後にも768 KiBの上限があります。成果物は仕事の正本に記録された変更のみで、任意のシェル出力は含みません。非Windowsの書き出しと元Projectへの自動適用は未対応です。
- 受入側で人の承認が必要な操作は、その端末での回答を待ちます。受付ONやtempの選択でフルアクセスにはならず、依頼元が受入側の実行権限を広げることもできません。
- 完了した元タスクの遠隔照会は無期限ではなく、24時間経過または完了元タスクの保持上限128件によってHubで退役します。端末へ保存済みの結果と取得済みの成果物は残ります。
- OSサービス運用、CA自体の入替の全端末への自動展開、手動MCP profileの接続者別pairing、N台の監視受入は未完了です。readモードへ書き込みtoolを公開したものではなく、全機能・全OS・全MCP clientの受入完了を示すものではありません。
