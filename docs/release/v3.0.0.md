# moyAI v3.0.0

## 開発版・未公開

Desktop 3.0.0とHub 0.1.0を組み合わせる開発版です。正式リリースではありません。実際の配布内容は各ZIPのmanifest、試験した版は対応するRESULTSとバイナリの識別情報で確認してください。公開済みv2.1.1の配布物は変更しません。

## 現行の変更

- **導入と端末登録**: `Setup-moyAI.cmd` による利用者単位の導入・更新と、接続ファイル `hub-config.moyai-join` の読込みに対応します。HubでPCの参加とプロジェクトの操作・実行用途を許可し、ID/PW入力は要求しません。同じWindowsユーザー名の別PCを自動統合しません。
- **共通のAI設定**: Hub設定があるPCは同じ「AIの接続」で標準または登録済みモデルを選びます。Runnerは実行PCのメインの選択を使います。Hub応答なしの接続リセットに対応し、手入力設定・ローカル会話・成果を保持します。
- **通常のプロジェクトと会話**: Hubプロジェクトは左の一覧に `MCP` 印付きで表示します。通常の入力欄から依頼し、AIが許可されたPCを選んで作業できます。各実行PCのフォルダーは端末上で登録し、既存ファイルも利用できます。
- **会話と参加の管理**: 共有チャットの新規作成・名前変更・削除、追加入力、停止、最新発言の編集・再送に対応します。最新発言の本文編集では元の画像・添付を保持します。離脱・参加解除・プロジェクト削除は新規利用を止め、実行中の処理の停止を確認します。再参加は新しい参加とし、フォルダーの専用探索や履歴復元処理は追加しません。
- **実行と成果**: Runnerが画面とは独立して実行し、Hubが会話・入力・公開成果を保持します。受信PCの使用中表示・送信制限・現地停止、子仕事の成果受渡し、起動したアプリの継続と停止を扱います。
- **承認と通知**: 別PCで実行する操作も、依頼元のPCで内容を確認して許可・拒否・停止します。対象PC・作業場所・具体的操作を表示し、Windowsにも通知します。子仕事の拒否・停止後に親AIが自動で別ルートを試すことを防ぎます。
- **復旧と表示**: 消失した作業フォルダーの再選択、モデル確認後に残る古い警告、Windowsでの書込み完了判定、操作失敗の表示を修正します。通常起動時は最後に開いた会話と作業フォルダーを復元します。
- **Hubの起動と受信許可**: 起動入口からブラウザー管理を開き、保存済みネットワークを再開します。Windowsの受信規則を照合し、必要時は対象を確認してUACで設定、または管理者向けスクリプトを保存できます。ブラウザーを閉じてもHubは継続します。

旧手動MCP配信・方向付き接続を新規導入の経路には使いません。互換性のための保存済み設定・資格・履歴・照会APIは維持します。新規利用手順は[使い始める](../user/getting-started.md)、[Hubプロジェクト](../shared-work-desktop.md)、[Windowsへの導入と更新](../user/windows-setup.md)を参照してください。

## 確認済みの範囲

2026-09-27の変更について、Rust・frontend・実Hubと2 Runner・実Tauriの回帰を実施しています。過去のLive成功を今回の版の合格へ流用せず、最終ソースのGUI・認証付きLive・暫定配布物の結果を分けて記録します。開発workspaceの結果は `project_sandbox/pre-physical-winab-20260927/RESULTS.md` を参照してください。

## 制限と残課題

- 最新発言の編集は実ファイルや起動済みアプリを巻き戻しません。画像・添付は元の内容を引き継ぎます。添付の追加・差替えは新しい発言で行います。現在の権限で利用できない添付は再送できません。
- 各PCのフォルダー全体は自動同期しません。入力・公開成果と会話の保存には個別の容量上限があります。
- 停止要求の受付・通信断と、プロセス停止の確認は別です。確認できない処理の枠を自動で再利用しません。
- 開発用LLMは当面、固定IPで接続しています。過去に生じた `.local` の名前解決不調の原因は未確定です。接続先は利用環境の設定を使い、固定IPを製品に埋め込みません。
- RunnerはWindows利用者のログオン中に動作します。OSサービス運用とHubのルートCAの全端末への自動入替は未対応です。

## 配布時の条件

DesktopとHubの両方を対応版へ更新してください。旧配布物の成功を現行実装の受入へ流用しません。公開用packageはcleanな確定commitから再ビルドし、版・commit付きの手動GUI証跡と同梱Hubの組合せ証跡を確認します。ZIP・manifest・SHA256、導入・更新後の実動作をそろえてから正式公開します。
