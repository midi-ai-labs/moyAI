# moyAI v1.2.1

## 日本語

v1.2.1では、ローカルLLMで長時間のcoding taskを進めるときのcontext継続性とtool failureからの回復を改善しました。製品defaultと主なbehavioral validation対象は`qwen/qwen3.6-27b`です。

### 主な変更

- automatic compactionのcheckpointを、作業状態、決定、確認済みevidence、未解決事項、次のactionを分離した構造で生成し、必須section・順序・非空条件を満たさないsummaryはcanonical historyへcommitしないようにしました。
- provider報告usageとlocal suffix estimateを使う既存のcontext判定を維持しつつ、compaction requestの出力上限を通常task requestから分離しました。
- tool failureをmodelへ返す際の総byte数をbounded化し、untrustedな長大出力が後続contextを占有し続けないようにしました。typed sandbox guidance等の信頼済み情報は保持します。
- `apply_patch`のmarker欠落やcontext mismatchを副作用前に短く分類し、source本文を再掲せず候補位置等の汎用的なrecovery evidenceを返します。
- file readのnot-found時に、workspace内のexact basename / suffix候補だけをboundedに提示します。類似名は自動解決せず、候補であることを明示します。
- shell commandの前後でもtyped edit baselineを保持します。shellが対象fileを置換または削除した場合、後続のwhole-file writeはstale baselineとしてfail closedし、外部変更を上書きしません。
- 共通base instructionへ小さなevidence ledgerを追加し、owner、直接consumer / verification、未確認・観測済み・conflictを整理して、必要な証拠が揃った後の探索反復を抑える方針にしました。
- 新規またはmodel未指定のconfigで使うdefaultを`qwen/qwen3.6-27b`へ変更し、README、getting-started、config example、Desktopの初期表示を同期しました。

### 更新時の注意

- 既存のuser configに明示されたprovider URL、model、context、output上限はそのまま優先され、default変更によって書き換えられません。
- persisted schemaとmigration versionは変更していません。既存project / session dataをそのまま利用できます。
- malformed compaction responseは自動修復せず、そのturnでは元のcanonical historyを維持します。hard context limitへ達した場合は従来どおり明示的に失敗します。
- shell後のstale whole-file write拒否はno-clobber動作です。意図的な変更はcurrent fileを再読してから適用してください。

## English

v1.2.1 improves context continuity and recovery from tool failures during long-running coding tasks with local LLMs. The shipped default and primary behaviorally validated profile is `qwen/qwen3.6-27b`.

### Highlights

- Generates automatic-compaction checkpoints with separate sections for working state, decisions, verified evidence, unresolved items, and next actions. A summary that is missing, reorders, or empties a required section is not committed to canonical history.
- Keeps the existing provider-usage plus local-suffix context accounting while separating the compaction request's output cap from normal task requests.
- Strictly bounds the total model-visible bytes of tool failures so untrusted long output does not continue occupying later context. Trusted typed guidance, including sandbox guidance, is retained.
- Classifies markerless and context-mismatched `apply_patch` requests before mutation and returns generic recovery evidence, such as bounded candidate positions, without echoing source content.
- Offers only bounded, exact basename or suffix candidates for missing workspace reads. Similar names remain explicitly non-resolving hints.
- Preserves typed edit baselines across shell commands. If a shell command replaces or deletes the target, a later whole-file write fails closed as stale instead of overwriting the external change.
- Adds a small evidence ledger to the common base instructions so the model can track the current owner, direct consumer or verification, and missing, observed, or conflicting evidence, then stop discovery after the required evidence is present.
- Changes the default for new or otherwise unspecified model configuration to `qwen/qwen3.6-27b` and synchronizes the README, getting-started guide, config example, and Desktop initial state.

### Upgrade notes

- Existing user configuration remains authoritative. Explicit provider URL, model, context, and output limits are not rewritten by the new default.
- This release does not change the persisted schema or migration version. Existing project and session data remain compatible.
- A malformed compaction response is not auto-repaired; canonical history remains unchanged for that turn. Reaching the hard context limit still fails explicitly.
- Rejecting a stale whole-file write after a shell command is intentional no-clobber behavior. Re-read the current file before applying an intended change.
