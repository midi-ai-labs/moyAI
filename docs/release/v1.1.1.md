# moyAI v1.1.1

## 日本語

v1.1.1では、Git repository内のnested directoryをworkspaceとして選択したとき、その選択directoryをtoolとsandboxの正確なauthority境界として扱うように修正しました。

### 主な変更

- ancestorのGit project rootと、ユーザーが選択したworkspace directoryの役割を分離しました。Git identity、project一覧、ancestor instruction探索にはproject rootを使い、tool accessとsandbox authorityには選択directoryを使います。
- Glob、read、write、apply_patch、workspace traversal、shell effect review、Windows workspace sandboxが、同じ選択directoryを境界として判定するように統一しました。siblingやancestorを誤ってworkspace内として代理承認しません。
- CLI、TUI、Desktopでsessionにexactなworkspace directoryを保存し、同じsessionを開き直したときもその境界を復元します。
- built-in Git review commandを選択directoryへscopeし、file-change表示は選択workspaceからの相対pathとして投影します。
- 自動Markdown exportを対象sessionのworkspace配下へ保存し、transcript metadataにもそのexact directoryを記録します。

### 更新時の注意

- persisted schemaとmigration versionは変更していません。既存のproject/session dataをそのまま利用できます。
- nested directoryの外側へアクセスする操作は、従来どおりpermission policy上のoutside-authority effectとして扱われます。
- Git repository root自体をworkspaceとして選んだ場合の挙動は変わりません。

### 検証

- nested workspace authorityのfocused regression、Rust full suite、Desktop Web test/build、all-features checkを実行しました。
- actual Tauri Desktopでnested workspaceを選択し、case5_2のStage 3までを同一sessionで確認しました。
- cleanなrelease commitからpackageを作成し、展開後のCLI version、manifest/checksum identity、bundled Desktop binaryのvisible smokeを確認しました。

## English

v1.1.1 fixes nested-directory workspace selection so the selected directory, rather than an ancestor Git root, remains the exact authority boundary for tools and sandboxing.

### Highlights

- Separated the ancestor Git project root from the user-selected workspace directory. The project root still owns Git identity, project listing, and ancestor-instruction discovery, while the selected directory owns tool access and sandbox authority.
- Made Glob, read, write, apply_patch, workspace traversal, shell-effect review, and the Windows workspace sandbox use the same selected-directory boundary. Siblings and ancestors are no longer misclassified as inside the workspace for delegated approval.
- Persisted and restored the exact workspace directory across CLI, TUI, and Desktop session reopen.
- Scoped built-in Git review commands to the selected directory and projected file changes relative to the selected workspace.
- Saved automatic Markdown exports under the target session's workspace and recorded that exact directory in transcript metadata.

### Upgrade notes

- This release does not change the persisted schema or migration version. Existing project and session data remain compatible.
- Operations that access paths outside the selected nested directory continue to be treated as outside-authority effects by the permission policy.
- Behavior is unchanged when the Git repository root itself is selected as the workspace.

### Verification

- Ran focused nested-workspace authority regressions, the Rust full suite, Desktop Web test/build, and the all-features check.
- Exercised nested-workspace selection through Stage 3 of case5_2 in the same actual Tauri Desktop session.
- Built the package from a clean release commit and verified extracted CLI version, manifest/checksum identity, and the bundled Desktop binary with a visible smoke test.
