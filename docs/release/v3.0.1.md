# moyAI v3.0.1

Windows x64向けの修正版です。Hubと組み合わせる場合はmoyAI Hub 0.1.0を使います。WebView2とx64 VC++ runtimeが導入済みのPCを対象とし、Setupは前提runtimeをダウンロードしません。

## 修正内容

Active DirectoryのドメインアカウントでWindowsへログオンしたPCで、`only a local SAM caller is supported by this broker token factory` と表示され、moyAIが起動できない問題に対応しました。3.0.0-rc.2までのローカルSAMアカウントだけを受け付ける判定を改め、ADドメインアカウントの起動と制限付き実行の経路を追加しました。

ローカルアカウントの実行経路を維持し、ADアカウントではKerberos S4Uで制限付き実行の資格を用意します。起動元と同じ利用者であること、通常権限であること、グループの拒否権限、操作ごとの所有者と書込み先の制限は引き続き検証します。通常のDesktop・CLI・Runnerを管理者として起動する必要はありません。

[3.0.0-rc.2](https://github.com/midi-ai-labs/moyAI/releases/tag/v3.0.0-rc.2)の機能と修正を引き継ぎます。

## AD環境の条件と制限

- PCがADドメインへ参加していること、ドメインコントローラーへ接続できること、共通helperが対象利用者のグループ所属を読み取れることが必要です。名前解決やドメインポリシーの制限で資格を用意できない場合は、コマンドの実行を中止します。
- 認証や制限付き実行の失敗を、フルアクセスでの自動再実行へ切り替えません。操作ごとの承認と「フルアクセス」の選択は従来どおりです。
- Microsoft Entra IDだけのアカウントは未対応です。この修正は、制限付きコマンドからのネットワーク共有へのアクセスを保証しません。
- 実際のADドメインコントローラーとドメインアカウントを使う実行は未確認です。ローカルアカウントでの試験やアカウント分類の単体試験を、AD環境での受入確認として扱いません。

## 更新

Desktop・CLI・Runnerの仕事を終了してから、新しいZIPを既存の導入先の外へ展開し、`Setup-moyAI.cmd` を通常権限で実行してください。共通helperの更新時は別画面で管理者承認が必要です。アプリと共通helperは同じ配布物で更新します。設定・履歴・成果を初期化する必要はありません。詳しくは[Windowsへの導入と更新](../user/windows-setup.md)を参照してください。

検証結果は開発workspaceの `project_sandbox/release-3.0.1-ad-20261021/RESULTS.md` と、版・commit・バイナリの識別情報を付けた配布証跡へ記録します。過去の候補の試験結果は今回のAD対応の受入確認へ流用しません。
