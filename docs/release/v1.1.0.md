# moyAI v1.1.0

## 日本語

v1.1.0では、長時間のローカルLLM開発タスクを最後まで進めやすくするため、再帰的なAgent Tree、context compaction、patch、Windows process実行のowner境界をCodexへ近づけました。

### 主な変更

- nested Sub Agentを含むspawn edge、mailbox、follow-up trigger、Stop fence、turn inputをcanonical storageへ保存し、process再起動後もexact ownerから再開できるdurable Agent Treeへ移行しました。
- root、child、detached descendantの完了・失敗・中断をtyped terminalとexact turn identityで確定し、staleなcompletion、mail、Stopが別ownerへ適用されないようにしました。
- context compactionをprovider requestのsemantic unitとdurable checkpointで管理し、実user input、assistant response、tool call/outputの順序とlineageをlive/replayで一致させました。
- `apply_patch`のUpdate grammar、named context、EOF append、大型fileのtargeted update/deleteをCodex型の利用方法へ揃えました。Windows shellは利用可能なら`pwsh`を優先します。
- Windows sandbox processごとのprivate TEMPとJob lifecycleを整理し、終了を証明できないprocess treeでは安全でない再実行やcleanupを行いません。restricted TEMPでWinError 5になった場合は、明示的にreviewed elevationを選べるtyped hintを表示します。
- local model向け既定値をrequest/stream idle各30分、`max_output_tokens=32768`へ更新しました。context working targetはoutput上限から独立してcontext windowの90%を使います。
- SUBST drive rootをprojectにした場合、実行・保存上のrootとProjectIdは論理drive pathのまま保ち、Desktopのproject表示名だけbacking folder名へ復元します。

### 更新時の注意

- 既存DBはV53までforward migrationされます。初回起動前にmoyAIのdata directoryをbackupしてください。
- request/stream timeoutとoutput上限の既定値が増えています。providerまたはGPUメモリの制約に合わせてconfigで明示的に下げられます。
- multi-agentの既定modeは明示的なdelegation依頼で有効になる`explicit_request_only`です。rootとdescendantは同じ通常tool/collaboration tool surfaceを持ちます。
- Windows `workspace-write` sandboxはunelevatedな有限既存object defenseであり、完全なnamespace isolation、firewall、private desktop、same-user host processからの隔離ではありません。

### 検証

- Rust full suite、Desktop Web test/build、all-features check、release buildを実行しました。
- actual Tauri DesktopでSUBST project表示、canonical recursive Agent Treeの保存投影、長時間case5_2の全stage完走を確認しました。
- cleanなrelease commitからpackageを作成し、展開後のCLI version、manifest/checksum identity、bundled Desktop binaryのvisible smokeを確認しました。

## English

v1.1.0 aligns recursive Agent Tree ownership, context compaction, patching, and Windows process execution more closely with Codex so long-running local-LLM development tasks can reach a clean terminal state.

### Highlights

- Moved nested Sub Agent spawn edges, mailboxes, follow-up triggers, Stop fences, and turn inputs into canonical storage, allowing the exact Agent Tree owner to recover after a process restart.
- Bound root, child, and detached-descendant completion, failure, and interruption to typed terminals and exact turn identities so stale completion, mail, or Stop events cannot cross owners.
- Made context compaction a durable, semantic provider-request operation while preserving real user input and assistant/tool ordering consistently across live execution and replay.
- Aligned `apply_patch` Update grammar, named contexts, EOF append, and targeted large-file update/delete behavior with Codex usage. Windows shell execution now prefers `pwsh` when available.
- Gave each Windows sandbox process a private TEMP and explicit Job lifecycle. moyAI avoids unsafe replay or cleanup when process-tree termination cannot be proven and projects a typed reviewed-elevation hint for restricted-TEMP WinError 5 failures.
- Updated local-model defaults to 30-minute request/stream-idle deadlines and `max_output_tokens=32768`. The context working target is now independently fixed at 90% of the context window.
- Preserved the logical drive path for workspace authority and ProjectId while restoring the backing-folder name in Desktop when a project is opened through a SUBST drive root.

### Upgrade notes

- Existing databases migrate forward through V53. Back up the moyAI data directory before first launch.
- Default request/stream deadlines and output limits are higher. Lower them explicitly in config when required by provider or GPU-memory constraints.
- The default multi-agent mode is `explicit_request_only`, enabled by an explicit delegation request. Root and descendant agents receive the same normal and collaboration tool surface.
- The Windows `workspace-write` sandbox is an unelevated, finite existing-object defense. It is not complete namespace isolation, a firewall, a private desktop, or isolation from same-user host processes.

### Verification

- Ran the Rust full suite, Desktop Web test/build, all-features check, and release build.
- Exercised SUBST project labels, canonical recursive Agent Tree persistence, and the complete long-running case5_2 route in an actual Tauri Desktop window.
- Built the package from a clean release commit and verified extracted CLI version, manifest/checksum identity, and the bundled Desktop binary with a visible smoke test.
