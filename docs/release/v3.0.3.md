# moyAI v3.0.3

Windows x64向けの修正版です。SetupでmoyAIを起動し、初期画面の描画が完了したことを確認するようにしました。引き続きmoyAI Hub 0.1.0と組み合わせて使います。

## 修正内容

`Setup-moyAI.cmd` は、アプリの配置後に通常の権限でmoyAIを起動します。splashの後に初期画面が描画されたことを確認してから、導入完了を表示します。利用準備は開いた画面から進めてください。この確認には、AIへの接続、PCの参加承認、最初の仕事の実行は含みません。

起動に失敗した場合は、エラーと診断ログの保存先を表示します。アプリの終了コード、起動結果、標準出力・標準エラー、OSとランタイムの情報を記録し、導入済みアプリと設定・履歴は保持します。ログは導入先の隣の `moyAI-setup-logs` フォルダーへ、実行ごとに分けて残します。導入先の名前を変更した場合は、その名前に `-setup-logs` を付けたフォルダーになります。

初期画面の表示完了を60秒以内に確認できなかった場合も成功にはせず、確認できなかった状態を表示します。セットアップはアプリを強制終了しません。後から画面が表示された場合は、その画面から通常どおり使うか「ファイル」→「終了」で閉じてください。セットアップをやり直す場合は、先にmoyAIを終了します。

非対話の集中配布では、配布物内の `scripts/Setup-moyAI.ps1 -SkipStartupCheck` で配置だけを行えます。起動確認を省略したことを表示するため、利用者が画面を開けることは別に確認してください。

## 引き継ぐ対応と動作条件

[3.0.2](https://github.com/midi-ai-labs/moyAI/releases/tag/v3.0.2)の待機中チャットの再描画修正と、[3.0.1](https://github.com/midi-ai-labs/moyAI/releases/tag/v3.0.1)のADドメインアカウント対応を引き継ぎます。この配布物はWebView2とx64 Visual C++ runtimeが導入済みのWindows x64 PC向けです。Setupは不足するランタイムをダウンロードしません。

Windows 10 2016 LTSBで報告された起動失敗の原因は、現時点で未確定です。この版の変更は失敗の表示と診断情報の記録を改善するもので、このOSで起動できることを実機で確認したものではありません。

ADアカウントで制限付きコマンドを実行するには、PCのADドメイン参加、ドメインコントローラーへの接続・名前解決、共通helperによる利用者のグループ所属の読取りが必要です。Microsoft Entra IDだけのアカウントは未対応です。AD環境からHubを使った動作報告はありますが、ADのtokenとグループに対するアクセス拒否を確かめる専用試験は未確認です。

## 更新

Desktop・CLI・Runnerの仕事を終了してから、新しいZIPを既存の導入先の外へ展開し、`Setup-moyAI.cmd` を通常権限で実行してください。共通helperの更新が必要な場合は、別画面で管理者承認を行います。アプリと共通helperは同じ配布物で更新します。設定・履歴・成果を初期化する必要はありません。詳しくは[Windowsへの導入と更新](../user/windows-setup.md)を参照してください。

検証結果は開発workspaceの `project_sandbox/setup-startup-check-20261023/`、`project_sandbox/release-3.0.3-startup-20261023/RESULTS.md` と、版・commit・バイナリの識別情報を付けた配布証跡へ記録します。
