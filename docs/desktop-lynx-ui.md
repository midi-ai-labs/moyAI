# Desktop LYNX の画面整理

2026-09-05。moyAI Desktop v3.0.0 の画面構成と操作。実装の正本は `ui/desktop-web/src/styles.css`、`render.ts` と既存の入力・画面更新 owner にある。

## 実画面で確認した課題

- 空の会話では見出しが上端へ寄り、入力欄との間に大きな空白があった。実行状態の欄が省略されると、会話領域が CSS Grid の伸縮行ではなく自動サイズ行へ配置されることが直接原因だった。
- プロジェクトとチャットに常に一定比率の高さを割り当てるため、件数が少なくても二つの一覧が離れていた。両側の固定ペインも会話の幅を圧迫していた。
- 空の会話はモデル・権限・プロジェクト情報をヘッダーと重複表示し、始め方より設定状態が目立っていた。「セッション未選択」という表示も入力できる状態と合っていなかった。
- 依頼の整形と送信がアイコン中心で、操作の意味を見分けにくかった。設定画面は小さな補足文字と混在する用語で、保存先や適用範囲を理解しにくい箇所が残っている。

## 今回の変更

Hub と共通するネイビー・ブルー・スレートを使い、Desktop のダーク画面を維持した。通常面、浮いた面、境界、補足文字を共通の色変数へ寄せた。警告、実行状態、権限、差分の意味を持つ色と形は維持する。

会話領域を明示した Grid 行へ配置し、実行状態欄の有無によらず残りの高さを使わせる。入力欄は引き続き既存の絶対配置と実測した `--composer-reserve` が所有する。左一覧は件数に沿って上から配置し、多い場合はプロジェクト一覧の高さを制限してそれぞれのスクロールを維持する。通常幅で左ペインは 260px、右ペインは 320px とした。既存の右ペイン開閉、狭い画面のドロワー、Side Chat は同じ操作を使う。

空の会話は LYNX の表示、依頼を始める見出し、短い案内、選択中プロジェクトに整理した。未選択時の見出しは「新しいチャット」と表示し、保存済みのセッション名は変更しない。実行欄は型付きの状態、現在の処理、直近ツール、停止操作を表示する。入力欄は「依頼を整える」「送信」を明示し、幅が足りない場合はボタンを折り返す。追加指示の可否と説明、入力 draft、フォーカス、IME、送信 target は既存 owner を使う。

左上の重複していた設定入口は「moyAI Hub」へ変更し、下部の「設定」は残した。Hub 接続・カタログ確認は専用の画面と状態 owner に分離する。カタログの確認完了を生成経路の利用可否と同一視しない。実際の Hub 連携範囲は [Hub integration](hub-integration.md) を参照する。

入力欄から Refresh を押した場合は、開始時の入力対象と操作世代が現在も一致するときだけ入力欄へ戻る。一般的なボタンのフォーカス復元が、この明示した復帰を妨げないよう整理した。Hub の Tab 移動はブラウザーが移動先を表示し、Hub 内のスクロールは即時に反映する。

続く実推論連携では、Hub画面のMain / Side各カードへ「直接接続 / Direct」「Hubを利用」を加えた。接続・モデル確認・送信先を別々に示し、未接続、未確認、編集中、実行中で切り替えられない理由を表示する。選択中の送信先は通常画面にも反映し、Hubの優先モデルと割当済みの実モデルを区別する。枠待ちとStopは既存の実行欄を使い、接続が切れたときもHub選択を保持して必要な確認を入力欄に案内する。Sideは先に既存の会話設定が必要であり、Hub経由の依頼の整形・並列サブエージェント実行は未対応と明示する。

## 検証と残る改善

以下のPASSは画面整理と接続・確認のincrementに対する証拠であり、後続のHub実行先切替や実モデル推論の検証を含まない。実推論連携は別の二アプリ実操作シナリオとtask-local evidenceで検証する。

2026-09-05 の最終 `shell.lynx` は actual Tauri / WebView2 で PASS（`e2e-20260905t085932z-915fe810`、17,722ms、diagnostics なし、cleanup PASS）。CSS の文字列だけで判定せず、実測レイアウト、trusted pointer / keyboard 入力、Rust projection と画面の対象一致から次を確認した。

- 待機中・実行中の会話領域が伸縮行を使い、実測した入力欄の高さに応じた余白が確保され、送信・停止が遮蔽されないこと。
- 日本語を含む長い入力と Refresh 後のフォーカス・選択位置・同一入力ノードの保持。
- 実際の送信から一件の scripted provider 要求を実行中に保持し、その間の polling でも未送信入力の内容・フォーカス・選択位置・ノードが保持されること。Stop 後は再要求せず待機状態へ戻ること。
- 1100×720 の CDP WebView viewport で、右ドロワー開閉と長文入力時にもレイアウトと主要操作が成立すること。これは native ウィンドウの resize 検証ではない。
- Settings の入力保持、未保存状態で閉じる際の確認、取り消し、明示的な破棄、閉じた後の会話入力の保持。

Hub の最終 `hub.connection-settings` も actual Desktop で PASS（`e2e-20260905t091042z-22eceffb`、20,435ms、cleanup PASS）。認証付き接続、Main / Side 別の確認・保存、カタログ更新時の編集中入力保持と明示的な再確認、切断と秘密情報を含まない保存値を確認した。実際のDesktop再起動後も選択を復元し、token空・未接続・未確認・暗黙HTTPなしを維持する。カタログ未取得のモデルは削除扱いせず「保存済みのモデル」と表示する。接続先は HTTP 契約を厳密に照合する fixture であり、実 Hub と Desktop の二つのウィンドウを同時操作した E2E ではない。

native IME の候補選択・変換操作、多数のプロジェクト／チャット一覧の操作、添付を含む入力欄、native resize は今回の検証対象に含まれない。会話履歴と添付の全組合せに対する表示保証や、実モデルの回答品質もこの PASS からは主張しない。合否と実行時の artifact identity の正本は task-local execution の `result.json` / `seal.json` と `RESULTS.md` にある。

## GUI評価を反映した操作

- Mainの実行中は「Mainを停止」、Sideの実行中は「Sideを停止」を文字付きで表示する。停止対象と承認・取消の境界は既存commandを使う。Sideが実行していないときに「停止不可」は表示しない。
- Mainの停止結果は日本語で示す。Sideの通常停止も日本語の案内として示し、停止後に起きた保存失敗などのエラーとは区別する。Hub利用時は、Desktopを停止してもHubがモデルの終了確認まで実行枠を保持することを案内する。画面の停止表示を上流モデルの強制停止と同一視しない。
- 狭い画面で出力を開いた場合、会話と初期案内・ヘッダーは出力ペインの手前に収める。幅変更でユーザーが開いた出力を自動的に閉じない。履歴ジャンプは本文から離れた「履歴」欄として表示し、既存anchorとキーボード操作を維持する。
- 「ファイル」→「moyAIを終了」はトレイの「終了」と同じ既存終了commandを呼ぶ。タイトルバーの×は従来どおりトレイへ格納し、Hub接続を解除する。×の説明に格納と完全終了の違いを示す。
- 設定画面は日本語の利用目的と入力条件を先に表示し、設定キー・型・環境変数等は「技術詳細」で確認する。設定値・保存範囲・入力の検証は変えない。

前段のGUI評価で全機能が検証済みになったわけではない。修正箇所の実操作、ビルド同一性、未確認範囲は `project_sandbox/lynx-hub-gui-fixes-20260905/RESULTS.md` に記録する。初回接続の案内や未計測の使用量表示など、今回の所見以外を変更するときもcurrent ownerから確認する。
