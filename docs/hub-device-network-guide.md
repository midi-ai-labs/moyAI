# Hubを使って端末を接続する

Desktop 3.0.0 / LYNXの開発版向けの手順です。端末連携を実装し、同一Windows上の実Hub/Desktop画面と分離した送受信runtimeで、共通設定からの開始・参加、temp受付・有向許可・利用先選択・承認、CPU調査結果の返却を確認しました。配布済みの旧ビルドにはこの画面や通信方式が含まれません。

物理複数Windows・3台再委任の受入は未実施です。Hub再起動をまたぐ再委任経路の復元と、Hub/Gatewayのサーバー証明書の連続稼働中の自動更新は未対応です。確認済みの操作と残る受入条件は [Hubで管理する端末接続](design/hub-device-network.md) を参照してください。

## 初回の準備

Hubの管理者は「端末ネットワーク」で、接続するDesktopから届くこのHubのIPv4とポートを指定し、ネットワークを開始します。モデル接続とGatewayもまとめて起動します。生成に使うモデルは「登録モデル」から登録します。従来の手動サーバーを別に開始する必要はありません。

Hubから共通設定を保存し、接続する各Desktopへ渡します。この設定に入るのはHubのURLと公開CA証明書です。秘密鍵や全端末共通の接続トークンをコピーする必要はありません。Hubの管理者が参加コードを発行し、対象端末で一度だけ使います。コードには期限があり、別の端末へ使い回しません。

Desktopで「moyAI Hub」→「端末連携」を開き、共通設定を読み込んで参加コードを入力します。初回設定画面からは「Hubの共通設定で始める」で共通設定を読み込めます。先にDirectモデルを登録する必要はありません。端末の鍵を生成し、Hubへ登録します。登録後も端末名が同じという理由だけで他の端末と同一視しません。再インストールや端末交換の場合は、新しい端末として管理者に確認してください。

## Win19・Win20でタスクを受け付ける

「この端末でタスクを受け付ける」で、初回に次を確認します。

- 作業場所：フォルダーに依存しない問い合わせは `temp`。開発作業は、このDesktopに登録したプロジェクトを選びます。
- 実行権限：その端末で許す操作の範囲を選びます。受付ONだけでフルアクセスにはなりません。
- モデル：通常はHubのモデル割当を使います。既存の直接接続設定を使う選択肢は詳細にあります。

確認後、受付をONにします。待受IP・ポート・TLS証明書・呼出用トークンの手入力は不要です。受付をOFFにすると新しい依頼を受け付けなくなります。受理済みの仕事を止める場合は、その仕事の停止操作を使ってください。

`temp` は、その端末上に用意する一時作業場所です。他のすべてのフォルダーを自由に操作できるという意味ではありません。CPU使用率の問い合わせも、受入側エージェントがその端末で許された操作として調査します。Hubの登録名がWindowsコンピューター名と異なっていても、選択した受入端末上で実行します。

## Win00から利用する

同じHubへの登録が済んだWin00で、接続先の一覧からWin19・Win20を検索して利用をONにします。表示される候補はHubが許可した公開対象です。Hubへの登録だけで全端末との相互接続が有効になることはありません。

「受付申告あり」はHubが受け取った公開状態です。各依頼時に相手への接続を確認します。

依頼をチャットに入力すると、エージェントが選択済みの利用先へタスクを委任できます。作業と結果の正本は実行した端末に残ります。接続元では委任先・状態・結果を確認します。通信できなくなった場合、最後に取得した状態と現在確認できた状態を区別し、別端末で勝手にやり直しません。

## グループと方向付きの許可

Win00–14を「クライアント」、Win15–20を「サーバー」としてHubのグループへ登録すれば、共通の許可をまとめて設定できます。両方の役割を持つ端末は両グループに所属できます。

| 許可の例 | 意味 |
| --- | --- |
| クライアント → サーバー、直接利用を許可 | Win00–14からWin15–20を選択して利用できる |
| サーバー → サーバー、直接利用を許可 | サーバー自身の仕事で別サーバーを利用できる |
| クライアント → サーバー、再委任を許可 | クライアント由来の仕事を、受入サーバーが許された別サーバーへ委任できる |
| Win00 → Win20、直接利用を拒否する個別例外 | Win00からWin20への直接利用を外す。再委任の許可は別に判断する |

許可には公開対象の条件も付けられます。共通規則の例外が必要な場合は、端末同士を指定する個別規則を使います。Desktopの利用ONでHubの拒否を上書きすることはできません。

Win00→Win19→Win20では、Win00の元の依頼であることを引き継ぎます。Win19が自身の広い権限へ置き換える仕組みではありません。循環する経路や許された深さ・総数を超える委任は拒否します。

## 停止・再接続

受付OFF、接続先の利用OFF、端末登録の失効、実行中の仕事の停止は、それぞれ対象が異なります。下位端末の終了を確認できるまで「停止済み」とは表示しません。Hubや実行端末へ到達できない場合は、実行端末のGUIでその仕事を確認・停止できます。

「接続を一時解除」は登録ID・公開対象・実行権限・利用先の選択を保持します。「再接続」で同じ登録に戻り、受付は手動でONにします。

Desktopの端末証明書の更新は端末ごとに自動で行います。共通なのはCAの公開信頼で、秘密鍵は各端末固有です。証明書は接続する組み合わせごとに用意しません。Hub停止・再起動後の回復と、別の物理Windows間の動作は、受入結果で確認済みの範囲を参照してください。

Hub / Gatewayのサーバー証明書は別で、有効期間30日の証明書をネットワーク開始時に生成します。連続稼働中の自動更新は未実装のため、管理者は期限前に仕事の終了を確認して計画的に停止・再開始してください。詳細と再接続への影響は [Hubの証明書の期限と計画停止](../../moyAI-Hub/docs/gateway.md#証明書の期限と計画停止) を参照してください。

「起動時に受付を開始」を選ばない場合、再起動後は受付ONを押して開始します。トレイ格納中の継続を選ばずウィンドウを隠した場合も、再表示後は手動で受付ONにします。保存した作業場所と権限が同じなら、初回の確認を繰り返す必要はありません。

Hubを再起動しても登録端末・許可・CAは保持されますが、実行中の委任資格の系譜は保持しません。再起動前に受理した仕事の遠隔照会・停止を再認可できない場合は、実行端末のGUIから確認・停止してください。未確認の仕事を自動で再実行しません。CA自体の入替を全端末へ自動展開する機能は未対応です。

従来の「MCPを配信」やURL・トークンを入力する接続設定は、手動で接続する互換機能として残ります。[従来のMCP配信](design/mcp-publish-foundation.md) の手順と、ここで説明したHub管理の端末連携を混同しないでください。
