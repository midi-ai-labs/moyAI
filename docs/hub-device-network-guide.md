# Hubを使ってPCとプロジェクトをつなぐ

各PCで共通設定を一度読み込み、管理者がHubでプロジェクトの操作PC・実行PCを選ぶと、Desktopの通常のプロジェクト一覧へ反映します。PCごとの接続先選択や、プロジェクトごとの利用者登録は不要です。仕事を依頼するPCと実行するPCは複数選べ、同じPCを両方に使えます。

## 管理者がHubの接続を準備する

Hubの管理画面は管理者用です。「PCの接続」で、各Desktopから到達できるHubのIPv4とポートを指定し、接続を開始します。モデル接続とGatewayもまとめて起動します。共有仕事やDesktopのチャットで使うAIは「登録モデル」で設定してください。

共通設定を配る前に、Hubを動かすWindowsでファイアウォールの受信許可を確認します。同じPCのDesktopから接続できても、別PCから届くとは限りません。

1. Hubの「接続状態を診断」で、現在待ち受けているHubとモデルGatewayのIP・TCPポートを確認します。
2. Hub PCのローカル管理画面で「このHub PCで受信許可を設定する」を開きます。実際に起動した `moyai-hub.exe`、HubとGatewayのポート、接続元とDomain／Privateプロファイルを確認して、必要な変更をWindowsへ依頼します。UACの確認が必要です。既存の規則で接続できる場合は重複追加しません。詳しくは[受信許可の手順](../../moyAI-Hub/docs/firewall.md)を参照してください。
3. 別PCのDesktopからも「Hubへの接続を診断」で確認します。ESET等が通信を管理している場合は、その製品の規則と遮断ログも確認します。

診断はファイアウォールを自動変更しません。ポートを限定した規則を使う場合は「接続と証明書の詳細」で固定ポートを設定し、次の開始後に実際の待受と一致することを確認します。アプリを別フォルダーへ展開した場合は、実行ファイルに対する規則のパスも見直してください。

「接続ファイルを保存」で `hub-config.moyai-join` を保存し、使うDesktopへ渡します。内容はHub URLと公開CA信頼です。各PCで同じファイルを使えます。端末の秘密鍵、人のパスワード、ログインの保存ファイルを配布する必要はありません。HubのIP・ポート・CAが同じなら、プロジェクトを追加するたびに共通設定を配り直す必要もありません。

## 各PCを一度登録する

1. Desktopの初期設定画面では「チームに参加する」から接続ファイルを読み込みます。設定済みの画面では「moyAI Hub」→「PCの接続」→「Hubの設定ファイルを読み込む」も使えます。Windowsユーザー名・PC名と接続に使うIPv4を取得し、そのPC固有の鍵で参加申請します。端末名や端末参加コードの手入力、先行するモデル設定は不要です。
2. Hub管理者は「接続PC」で申請を確認し、対象の「許可」を押します。Windowsユーザー名とPC名は申告情報なので、接続元IP・申請日時・端末の識別情報も照合してください。
3. Desktopが端末証明書を取得して自動接続します。コードの受け渡しや再起動は不要です。

参加申請中の通常の更新・再起動では、同じ端末鍵で申請を再開します。再インストールや端末交換で鍵が変わった場合は、新しい申請として管理者が確認します。同じPC名だけで以前の端末と同一視しません。

Windowsでは端末の秘密鍵を現在のWindows利用者だけが開けるように保護します。旧形式の鍵は初回利用時に自動で移行し、PCの登録は維持します。設定フォルダーを別のWindows利用者へコピーしても、その鍵は使えません。元のWindows利用者で起動するか、管理者にPCの再登録を依頼してください。追加のパスワード入力は不要です。

## PCをプロジェクトに割り当てる

Hubの「プロジェクト」で「プロジェクトを追加」を押し、名前と使うPCを選びます。「操作に使う」は依頼・成果の確認、「仕事を実行する」は作業を担当するPCです。同じPCを両方に選べます。準備中の実行PCも保存でき、準備状態はプロジェクトに表示します。

PCの参加承認時に専用の利用者が自動で作られます。ユーザー名・パスワードの設定や別のログインは不要です。同じ人の旧アカウント・別PCを引き継ぐ場合だけ、Hub管理者が詳細設定で利用者を結び付けます。既存の閲覧などの役割は保持・優先します。端末の参加だけで全プロジェクトやHub管理を許可しません。

実行に使うPCでは一度だけ「moyAI Hub」→「PCの接続」→「このPCで仕事を実行」を設定します。「実行する操作の確認」と「保存先フォルダーを選ぶ」で範囲を確認し、「この設定で実行を許可」を押します。AIはHubの標準モデルを使います。変更する場合は、このPCの「設定」→「AIの接続」でメインのモデルを選びます。

準備後は実行機能が自動で起動・再接続し、Hubの割り当てに従って作業フォルダーを作ります。通常はRunnerを手動起動したり、フォルダーをローカルプロジェクトへ登録して配信設定したりする必要はありません。保存先と権限の確認は、後から同じPCへプロジェクトを追加しても繰り返しません。同じHub・端末資格・公開CAを検証したURL変更でも保存済みの許可を保持します。別Hubや端末資格へは流用しません。

一台のPCを複数プロジェクトへ割り当てても、標準では同じPCの共通枠を使い、同時利用数は1です。プロジェクトを増やすたびに、そのPCの実行枠が増えるわけではありません。詳細は [実行PCの設定と運用](runner-shared.md) を参照してください。

## Desktopの通常の一覧から使う

端末の接続と操作用途の指定が済むと、許可されたHubプロジェクトがDesktopの左の一覧へ表示されます。別途ログインする必要はありません。依頼するだけなら、ローカルプロジェクトやモデル設定は不要です。

同じWindows利用環境・登録PC・Hubでは、起動時と資格の期限後に現在の登録・利用者の対応・権限を自動で再確認します。Hub管理者がPCを停止すると新しい仕事の受付・実行を止め、既存の仕事の確認・終了操作は維持します。端末資格の失効や、対応する利用者の変更・停止後は、以前の資格で通常の操作を続けられません。失効した実行PCでも、有効期限内の同じ端末証明書を確認できる場合は、受理済みの仕事の停止照合・不確定報告だけを受け付けます。

プロジェクトの「新しいチャット」からメッセージを送ります。実行PCが一つなら自動で選び、名前も依頼内容から作ります。承認や成果の受け取り、別PCからの会話の継続は、同じプロジェクトの会話で行います。[DesktopのHubプロジェクト](shared-work-desktop.md) に操作をまとめています。

実行PCとDesktopはHubへ接続して割り当てと結果をやり取りします。この共有仕事のために、各PCで個別moyAI MCPの待受ポートを開けたり、PC同士の直接接続を設定したりする必要はありません。Hubの通信と、必要なモデル接続先への通信を許可してください。

## 接続や実行を確認する

Desktopの「PCの接続」→「接続の詳細・診断」にある「Hubへの接続を診断」で、保存済みの接続先へのTCP・TLS・Hubの許可を確認します。このPCでHub経由のAIを使う場合だけ、追加のGateway診断も行います。共有仕事を操作するだけのPCにはGatewayへの接続を要求しません。「未実施」は成功を意味しません。失敗した段階の案内を確認し、必要なら「再接続・最新情報を取得」や「参加申請を再試行」を使います。

Hubの「接続状態を診断」はHub側の状態を確認します。Hub内の確認だけで、別PCから到達できるとは確定しません。別PCからの接続診断と、プロジェクトでの仕事の実行はそれぞれ確認してください。

プロジェクトの「PCの利用状況」と会話には、実行機能の通信応答と最終応答時刻を表示します。15秒以上応答がない場合は「PCの応答なし（状態不明）」、Hub再起動後は新しい応答まで未確認です。操作PCの画面更新は、実行PCの応答には数えません。これは通信の観測で、処理の進捗や正常終了の保証ではありません。通信が切れても仕事や占有枠を勝手に解除しません。

## 停止・再接続・モデル設定

- 会話の「実行を停止」は、親と子の仕事全体へ取消を要求します。停止を確認するまで枠を保持します。
- 実行PCの「新しい仕事の受付を一時停止」は、新しい受付だけを止めます。Desktopを閉じることや接続解除でも、実行中の仕事は止まりません。
- Hubの端末の「停止」は新しい利用を止めます。状態の照合や受理済みの終了通知は別に扱います。「再許可」で古い実行許可を復活させるものではありません。
- 「接続を一時解除」はPCの登録を保持します。同じ設定で再接続できます。端末資格の恒久的な失効は、通常の一時解除とは異なる操作です。

「設定」のAIの接続欄でMain・Sideのモデルを独立に選び、保存します。Hub設定済みのPCでは接続先と方式は表示専用で、「Hubの標準モデル」または登録候補をドロップダウンから選べます。共有仕事には実行PCのMainの選択を使います。Hub停止中も手動入力へ戻さず、保存済みの選択を保持します。以前の手動設定へ戻す場合は「接続設定をリセット」を使います。

端末の秘密鍵は各PC固有です。通常の端末証明書更新で共通設定を配り直す必要はありません。同じHub・同じ公開CAでURLやポートが変わる場合は、新しい接続ファイルを読み込み、確認画面で変更を承認します。Desktopは既存の端末証明書で移動先へ接続し、Hub ID・端末ID・証明書情報が一致した場合だけ保存します。検証や保存が失敗した場合は元の接続設定を保持します。登録ID・秘密鍵・利用者の対応・履歴は変更しません。

実行PCは先に受付を一時停止し、実行中・状態不明の仕事を解消してください。Runner自身が待機状態を確認して正常終了した後に移行し、次の起動も受付停止を維持します。新しい接続を確認してから明示的に受付を再開します。停止後に保存できなかった場合も、元の接続で受付を自動再開しません。別Hubへの移動や公開CA変更はこの手順の対象外です。保存データの初期化や別端末としての自動登録は行いません。サーバー証明書の更新・期限・保守は [HubのGatewayと証明書](../../moyAI-Hub/docs/gateway.md) を参照してください。

## 旧版の個別連携を使っていた場合

「PCの接続」の「以前の接続で保存した利用先」では、このPCに残った旧利用先を削除できます。表示名に加えて端末IDと公開IDを確認し、対象の確認欄を選択して削除します。Hubから消えた端末も整理できます。Hub側の利用許可、別の登録、履歴、実行中の仕事は変更しません。新しい個別接続を追加する操作は提供しません。

個別moyAI MCPで新しい仕事を依頼する設定は廃止しました。旧設定や履歴を、新しいプロジェクト権限へ自動変換して実行を再開することはありません。Hubで使うPCを設定し、実行PCで保存先と権限を確認してください。

保存済みの記録は、設定の「汎用MCP」にある「過去の連携履歴」から確認できます。古い仕事の状態確認・停止の経路は維持します。汎用の外部MCPへの接続設定も引き続き利用できます。旧履歴の扱いは [MCP履歴](mcp-history-guide.md) を参照してください。

## Hubが故障・交換されたとき

AIの接続設定、または「PCの接続」の「接続設定をリセット」を開き、影響を確認して実行します。旧Hubが停止していても、このPCだけで接続情報・端末資格・モデル選択・旧実行許可を解除できます。Hub管理者の承認や、旧仕事の完了待ちは不要です。旧Hub側の登録削除・資格失効まで行ったことにはなりません。

履歴、成果ファイル、作業フォルダー、以前の手動AI設定は保持します。手動AIを利用するか、新しいHubの接続ファイルを読み込んで改めて参加承認を受けてください。同じURLで証明書が変わったHubにも、この手順で参加できます。新しい端末鍵を使い、旧資格や旧権限を引き継ぎません。

このPCの旧実行には停止を要求しますが、停止確認をリセット完了の条件にはしません。以前の仕事の未確認記録は保持し、新しいHubへ再投入したり完了扱いにしたりしません。新しいHubで実行を許可する際は、以前の処理と関連プロセスの停止、ファイル・外部システムへの影響を現地で確認してチェックしてください。新しい保存先と実行許可も確認し直します。

保存途中で終了した場合も旧Hubへ自動で戻りません。「前回の接続リセットを完了できていません」と出たときはリセットをもう一度実行してください。一時的な通信切れや通常の「接続を一時解除」では、このリセットを自動実行しません。
