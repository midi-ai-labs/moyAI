# Hubを使ってPCとプロジェクトをつなぐ

Hubで各PCを登録し、プロジェクトの操作PC・実行PCを選びます。操作PCのDesktopにはそのプロジェクトが `[MCP]` 印付きで現れ、通常のチャットから依頼できます。同じPCを両用途に使え、PCごとのID/PWログインや接続ペア設定は不要です。

## 管理者がHubの接続を準備する

1. Hubの管理画面を開き、「登録モデル」で利用するAIを登録します。Hubがモデルを起動・downloadする機能ではないため、接続先のAIサーバーは稼働させてください。
2. 「PCの接続」で各Desktopから到達できるHubのIPv4とportを選び、受付を開始します。HubとモデルGatewayの実際の待受を「接続状態を診断」で確認します。
3. Hub PCの「Windowsの受信許可」で、稼働exe・port・信頼する接続元・Domain/Privateを確認して設定します。適用時はUACを使います。[受信許可の手順](../../moyAI-Hub/docs/firewall.md) を参照してください。
4. 「接続ファイルの配布」の「接続ファイルを保存」から `hub-config.moyai-join` を出力し、参加するPCへ渡します。最初の一台専用ではなく、同じHubへ参加する各PCで使えます。

接続ファイルに入るのはHub URLと公開CAです。端末の秘密鍵は配布しません。Hub URL/CAが変わらなければ、プロジェクト追加のたびにファイルを配り直す必要はありません。

Hub PC内での接続成功は別PCからの到達を保証しません。Windows以外のセキュリティ製品や組織の規則が通信を管理している場合は、その管理者の設定を確認します。FWを無効化して確認する手順にはしません。実行ファイルを移設した場合は規則が旧配置を指していないか確認してください。

## 各PCを登録し、プロジェクトへ割り当てる

1. Desktopの初期設定の「チームに参加する」、または「moyAI Hub」→「PCの接続」で接続ファイルを読み込みます。AIサーバーのURLや参加コードを先に入力する必要はありません。
2. Hub管理者が「接続PC」で申請元のWindowsユーザー名・PC名・IP・申請日時・識別情報を確認し、名前を付けて許可します。名前は参考情報で、端末固有の鍵に対して承認します。
3. Hubの「プロジェクト」で名前と使うPCを選びます。「操作に使う」は依頼と成果確認、「仕事を実行する」は実作業を行うPCです。
4. 実行PCでは「このPCで仕事を実行」から保存先と権限を確認し、割り当てられたプロジェクトごとに「作業フォルダーを選ぶ」で登録します。既存フォルダーも使えます。**Hubの割当だけで作業フォルダーを自動作成する方式ではありません。**

PC側の実行許可とHubの用途指定はどちらが先でも構いません。準備前の実行PCには仕事を割り当てず、画面に必要な設定を示します。保存済みの実行同意を毎回取り直す必要はありません。プロジェクトを増やしても標準のPC共通実行枠は増えません。

通常参加では専用の非管理者の利用者対応をHubが準備します。同じ人の旧アカウントへ明示的に結び付ける場合だけ管理者が詳細設定を使い、通常参加から全projectやHub管理権限を付与しません。Windowsの秘密鍵は現在のOS利用者に保護されるため、設定フォルダーを別PCや別利用者へコピーして登録を引き継がないでください。

## 通常のチャットから使う

操作PCのプロジェクト一覧から `[MCP]` 印の行を開き、目的を入力します。初期進行役はHubが選び、工程ごとのPC利用はAIが現在の許可内で判断します。依頼だけのPCにlocal AIや作業フォルダーは不要です。

添付・承認・停止・成果保存・同じ会話の継続は [DesktopのHubプロジェクト](shared-work-desktop.md) にまとめています。新しい仕事はHubと独立Runnerでやり取りするため、各PCで個別moyAI MCPの待受や相互の接続ペアを設定しません。開発したFlask等のアプリへ別PCから接続する場合は、そのアプリの待受・FWを別に確認します。

Hubに参加済みのAI接続欄はURLが表示専用となり、Main/Sideのモデルを独立に選べます。共有Runnerは実行PCのMain選択を使います。Hubの一時停止では手動AIへ切り替えません。選択・変更確認の扱いは [Hubモデル連携](hub-integration.md) を参照してください。

## 接続と状態を確認する

Desktopの「接続の詳細・診断」→「Hubへの接続を診断」で、そのPCからのTCP・TLS・許可を確認します。そのPC自身がHub AIを使う場合だけGateway診断も行います。Hub内部の診断、「未実施」、model一覧取得を、別PCの到達や仕事成功と同一視しません。

「PCの利用状況」は実行準備・占有・Runnerの応答を分けて示します。通信が不明でも仕事と枠を解放せず、操作PCで画面を更新しただけではRunnerの応答には数えません。最初の生成・成果の往復はプロジェクトのサンプル依頼で確認できます。

## 停止・移設・故障

| 目的 | 操作 |
| --- | --- |
| 進行中の仕事を止める | 会話の停止、または受信PCの現地停止。実停止を確認するまで処理中 |
| 新規の仕事だけ止める | 実行PCの「新しい仕事の受付を一時停止」。実行中の停止とは別 |
| 特定projectから外れる | Desktopの「プロジェクトから離脱」。このPCの両用途を解除し、フォルダー・成果は保持 |
| 同じHubのURL/portを変更 | 新しい接続ファイルを読み、既存資格で同一Hub/CAを検証して保存。実行PCは受付を止め仕事を解消し、変更後に明示再開 |
| Hub故障・別Hub/CAへ交換 | 「接続設定をリセット」。旧Hubの応答不要でこのPCの資格と許可を解除し、新Hubで登録・実行許可をやり直す |

リセットは履歴・成果・作業フォルダー・以前の手動AI設定を残します。旧仕事の停止を要求しますが、停止確認をリセットの条件にしません。新Hubで実行を許可する前に旧処理の停止と外部への影響を現地で確認します。途中終了しても旧Hubへ自動復帰せず、リセット再試行を案内します。

旧個別連携の利用先は「以前の接続で保存した利用先」で対象IDを確認して整理できます。履歴・停止・成果取得は維持し、新規の個別接続や旧配信の自動再開は行いません。[MCP履歴](mcp-history-guide.md)、[共有Runnerの保守](runner-shared.md) も参照してください。
