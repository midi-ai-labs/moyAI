# Hubを使ってPCとプロジェクトをつなぐ

各PCで共通設定を一度読み込み、管理者がHubでプロジェクトの参加者・操作PC・実行PCを選ぶと、Desktopの通常のプロジェクト一覧へ反映します。PCごとの接続先選択や、プロジェクトごとの利用者登録は不要です。仕事を依頼するPCと実行するPCは複数選べ、同じPCを両方に使えます。

## 管理者がHubの接続を準備する

Hubの管理画面は管理者用です。「Desktopの接続」で、各Desktopから到達できるHubのIPv4とポートを指定し、接続を開始します。モデル接続とGatewayもまとめて起動します。モデルを共有する場合は「登録モデル」で設定してください。

共通設定を配る前に、Hubを動かすWindowsでファイアウォールの受信許可を確認します。同じPCのDesktopから接続できても、別PCから届くとは限りません。

1. Hubの「接続状態を診断」で、現在待ち受けているHubとモデルGatewayのIP・TCPポートを確認します。
2. 必要な受信許可がなければ、管理者が実際に起動した `moyai-hub.exe` のパスと上記ポート、利用する社内LANからの通信に限定して設定します。信頼する社内LANではPrivateプロファイルを使います。既存の規則で接続できる場合は重複追加しません。
3. 別PCのDesktopからも「Hubへの接続を診断」で確認します。ESET等が通信を管理している場合は、その製品の規則と遮断ログも確認します。

診断はファイアウォールを自動変更しません。ポートを限定した規則を使う場合は「接続と証明書の詳細」で固定ポートを設定し、次の開始後に実際の待受と一致することを確認します。アプリを別フォルダーへ展開した場合は、実行ファイルに対する規則のパスも見直してください。

「接続ファイルを保存」で `hub-config.toml` を保存し、使うDesktopへ渡します。内容はHub URLと公開CA信頼です。各PCで同じファイルを使えます。端末の秘密鍵、人のパスワード、ログインの保存ファイルを配布する必要はありません。HubのIP・ポート・CAが同じなら、プロジェクトを追加するたびに共通設定を配り直す必要もありません。

## 各PCを一度登録する

1. Desktopの初期設定画面では「Hubの共通設定で始める」、設定済みの画面では「moyAI Hub」→「端末連携」→「Hubの設定ファイルを読み込む」を使います。PC名と接続に使うIPv4を取得し、そのPC固有の鍵で参加申請します。名前や参加コードの手入力、先行するモデル設定は不要です。
2. Hub管理者は「接続端末」で申請を確認し、対象の「許可」を押します。PC名は申告名なので、接続元IP・申請日時・端末の識別情報も照合してください。
3. Desktopが端末証明書を取得して自動接続します。コードの受け渡しや再起動は不要です。

参加申請中の通常の更新・再起動では、同じ端末鍵で申請を再開します。再インストールや端末交換で鍵が変わった場合は、新しい申請として管理者が確認します。同じPC名だけで以前の端末と同一視しません。

## 人とPCをプロジェクトにまとめる

Hubの「プロジェクトと人」で設定します。

1. 「人」で利用者を登録し、初期パスワードを安全な方法で本人へ渡します。一人をプロジェクトごとに登録し直す必要はありません。
2. 「プロジェクト」で「プロジェクトを追加」を押し、名前を付けます。「参加する人」で閲覧・仕事の投入と実行・プロジェクト管理の権限を選びます。
3. 「使うPC」で「操作に使う」と「仕事を実行する」を選んで保存します。同じPCを両方に選べます。準備中の実行PCも保存でき、以後の準備状態はプロジェクトへ表示します。

利用できるプロジェクトは、人の権限とそのPCの用途の両方で決まります。PC登録を許可しただけでは、そのPCを使う全員へ仕事の閲覧・操作権限を与えません。Hub管理者にも、仕事の本文を読む権限は自動で付きません。

実行に使うPCでは一度だけ「moyAI Hub」→「端末連携」→「このPCで仕事を実行」を設定します。「実行する操作の確認」と「保存先フォルダーを選ぶ」で範囲を確認し、「この設定で実行を許可」を押します。このPCには実行に使うAIの接続・モデル設定も必要です。

準備後は実行機能が自動で起動・再接続し、Hubの割り当てに従って作業フォルダーを作ります。通常はRunnerを手動起動したり、フォルダーをローカルプロジェクトへ登録して配信設定したりする必要はありません。保存先と権限の確認は、後から同じPCへプロジェクトを追加しても繰り返しません。接続先や端末資格を変更した場合は再確認します。

一台のPCを複数プロジェクトへ割り当てても、標準では同じPCの共通枠を使い、同時利用数は1です。プロジェクトを増やすたびに、そのPCの実行枠が増えるわけではありません。詳細は [実行PCの設定と運用](runner-shared.md) を参照してください。

## Desktopの通常の一覧から使う

端末の接続後、「ログイン・プロジェクトへ」から利用者名とパスワードで初回ログインします。割り当てられたプロジェクトは左の一覧へ自動で表示されます。依頼するだけなら、ローカルプロジェクトやモデル設定は不要です。

同じWindowsユーザー・登録PC・Hubでは、再起動後や通常のセッション期限後もログインを継続します。パスワードを保存せず、端末に結び付く継続用の資格情報をDPAPIで保護します。プロジェクトを切り替えてもログインをやり直しません。「アカウント」から明示的にログアウトすると、自動ログインも解除します。利用者の無効化・パスワード再設定・端末資格の失効も再確認されます。

プロジェクトの「新しいチャット」からメッセージを送ります。実行PCが一つなら自動で選び、名前も依頼内容から作ります。承認や成果の受け取り、別PCからの会話の継続は、同じプロジェクトの会話で行います。[DesktopのHubプロジェクト](shared-work-desktop.md) に操作をまとめています。

実行PCとDesktopはHubへ接続して割り当てと結果をやり取りします。この共有仕事のために、各PCで個別moyAI MCPの待受ポートを開けたり、PC同士の直接接続を設定したりする必要はありません。Hubの通信と、必要なモデル接続先への通信を許可してください。

## 接続や実行を確認する

Desktopの「端末連携」→「接続の詳細・診断」にある「Hubへの接続を診断」で、保存済みの接続先へのTCP・TLS・Hubの許可を確認します。「未実施」は成功を意味しません。失敗した段階の案内を確認し、必要なら「再接続・最新情報を取得」や「参加申請を再試行」を使います。

Hubの「接続状態を診断」はHub側の状態を確認します。Hub内の確認だけで、別PCから到達できるとは確定しません。別PCからの接続診断と、プロジェクトでの仕事の実行はそれぞれ確認してください。

プロジェクトの「PCの利用状況」と会話には、実行機能の通信応答と最終応答時刻を表示します。15秒以上応答がない場合は「PCの応答なし（状態不明）」、Hub再起動後は新しい応答まで未確認です。操作PCの画面更新は、実行PCの応答には数えません。これは通信の観測で、処理の進捗や正常終了の保証ではありません。通信が切れても仕事や占有枠を勝手に解除しません。

## 停止・再接続・モデル設定

- 会話の「実行を停止」は、親と子の仕事全体へ取消を要求します。停止を確認するまで枠を保持します。
- 実行PCの「新しい仕事の受付を一時停止」は、新しい受付だけを止めます。Desktopを閉じることやHub利用者のログアウトでも、実行中の仕事は止まりません。
- Hubの端末の「停止」は新しい利用を止めます。状態の照合や受理済みの終了通知は別に扱います。「再許可」で古い実行許可を復活させるものではありません。
- 「接続を一時解除」はPCの登録を保持します。同じ設定で再接続できます。端末資格の恒久的な失効は、通常の一時解除とは異なる操作です。

ローカルのチャットでHubのモデルを使う場合は「端末連携」→「このPCのチャットでHubのモデルを利用」から「モデルを選ぶ」を開きます。「モデル割当」でMain・Sideの候補と変更点を確認し、保存します。既存のDirect設定がある場合は、選んだモデルを保存して「Hubを利用」へ切り替えます。実行PCが使うモデルの設定とはPCごとに区別されます。

端末の秘密鍵は各PC固有です。通常の端末証明書更新で共通設定を配り直す必要はありません。HubのIP・ポートやCA自体を変更する場合は、接続ファイルとファイアウォール規則を確認してください。サーバー証明書の更新・期限・保守は [HubのGatewayと証明書](../../moyAI-Hub/docs/gateway.md) を参照してください。

## 旧版の個別連携を使っていた場合

個別moyAI MCPで新しい仕事を依頼する設定は廃止しました。旧設定や履歴を、新しいプロジェクト権限へ自動変換して実行を再開することはありません。Hubで参加者と使うPCを設定し、実行PCで保存先と権限を確認してください。

保存済みの記録は、設定の「汎用MCP」にある「過去の連携履歴」から確認できます。古い仕事の状態確認・停止の経路は維持します。汎用の外部MCPへの接続設定も引き続き利用できます。旧履歴の扱いは [MCP履歴](mcp-history-guide.md) を参照してください。
