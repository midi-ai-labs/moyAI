# Windowsへの導入と更新

この手順は、`Setup-moyAI.cmd` と `deployment.json` を含む開発版配布物に適用します。旧v2.1.1 ZIPの配置は変更されません。実行先はWindows 10以降のx64です。

まず全員が下の「導入して開く」を行い、その後は担当に合った入口を選んでください。同じ人やPCが複数を担当することもできます。

| 担当すること | 初回画面で選ぶ入口 | 用意するもの・次の作業 |
| --- | --- | --- |
| WinAから仕事を依頼し、結果を見る | チームに参加する | 管理者から接続ファイルを受け取り、[チームへの参加手順](getting-started.md#チームで使う)を進めます。このPCのAI・モデル設定とHub本体は不要です。 |
| WinBで仕事を実行する | チームの仕事をこのPCで実行する | 管理者から接続ファイルを受け取り、PCの参加を申請します。AIはHubの設定を使い、必要なら「AIの接続」でモデルを選択します。承認後に[保存先と操作の許可](../shared-work-desktop.md)を設定します。Hub管理者がこのPCをプロジェクトへ割り当てます。 |
| チームのHubを管理する | チーム環境を用意する | Hub同梱版を使い、[管理者の準備手順](../../../moyAI-Hub/docs/team-preparation.md)で接続・PCの参加許可・プロジェクトを設定します。 |
| このPCだけで個人の仕事をする | 自分のPCで使う | 利用するAIの接続先とモデルを設定します。Hubへの参加は不要です。 |

最初の仕事には、管理者によるPCの参加許可とプロジェクトの操作PC・実行PCの指定、WinBの実行設定が必要です。インストール後にWinAだけを操作しても、これらの準備は完了しません。

## 導入して開く

1. 社内の信頼できる配布元から一式を受け取り、ZIPをフォルダーごと展開します。配布元が示すZIPのSHA256も確認します。
2. `Setup-moyAI.cmd` を通常の権限で開きます。PC共通sandbox helperが未導入、または配布物と異なる場合だけ、別の管理者承認画面が開きます。承認を取り消すと、利用者側アプリの導入前に中止します。承認後は通常の権限で現在のWindows利用者の `%LOCALAPPDATA%\Programs\moyAI` にアプリを配置し、スタートメニューへ「moyAI」を追加します。ダウンロードは行いません。
3. 配置後、セットアップが通常の権限でmoyAIを起動します。初期画面の描画完了をアプリから受け取ると、起動確認の成功と導入完了を表示します。moyAIの画面は開いたまま使えます。セットアップの画面は任意のキーを押して閉じます。次回からは**Windowsのスタートメニューの「moyAI」**を開きます。
4. 初回画面では上の表に合った入口を選びます。通常起動時の管理者承認はありません。起動確認では、PC参加・プロジェクトでの用途指定・仕事の実行準備までは確認しません。

管理者が導入する共通helperは、WindowsのProgram Files配下の `moyAI\SandboxService\moyai-sandbox.exe` と、手動開始の `MoyAISandbox` サービスです。LocalSystemで必要時だけ起動し、利用がなくなれば停止します。Windows起動時の自動開始には設定しません。実行物・登録設定は管理者とSYSTEMだけが変更でき、通常利用者はサービスの照会と開始だけができます。Desktop・CLI・Runnerの通常起動やRunnerのログオン時自動起動にUACは不要です。画面と仕事のコマンドは通常の利用者の権限で動作し、許可された場所への書込み制限と、操作ごとの確認は引き続き適用します。旧方式の `moyAI\Sandbox` 配下は、このSetupでは移動・削除しません。

Setup全体を「管理者として実行」しないでください。設定・履歴・ショートカット・接続ファイルの関連付けは元のWindows利用者が所有します。共通helperが欠けている、変更されている、またはアプリと版が合わない場合は起動を止め、配布物のSetupによる更新を案内します。起動時に利用者フォルダーからSYSTEM用実行物をコピーし直すことはありません。

3.0.1以降は、ローカルWindowsアカウントに加え、Active DirectoryのドメインアカウントでログオンしたPCも対象です。ADアカウントで制限付きコマンドを実行するには、PCがドメインに参加し、ドメインコントローラーへ接続でき、共通helperが利用者のグループ所属を読み取れる必要があります。名前解決・認証・ドメインポリシーの条件を満たせない場合は操作を中止します。社内LANへの接続や必要なVPN、ドメインの権限設定は社内管理者へ確認してください。Microsoft Entra IDだけのアカウントは未対応です。AD環境での実機確認状況は[3.0.3リリースノート](https://github.com/midi-ai-labs/moyAI/releases/tag/v3.0.3)を参照してください。

完了できなかった場合も表示は残ります。原因と「次の操作」を確認してから閉じてください。起動確認に失敗した場合は、エラー全文・終了コードまたは確認待ちの状態・ログの保存先を表示します。導入済みのアプリと設定・履歴は保持します。解消しない場合は、表示とログを社内の配布担当へ伝えてください。設定や履歴を初期化する必要はありません。

起動確認のログは、導入先の名前に `-setup-logs` を付けた隣のフォルダーへ、実行ごとに分けて保存します。既定では `%LOCALAPPDATA%\Programs\moyAI-setup-logs\setup-...` です。初期画面の表示完了を60秒以内に確認できなかった場合も成功にはせず、確認できなかった状態とプロセスの情報を残します。この場合、セットアップはアプリを強制終了しません。画面が後から表示された場合は、その画面から通常どおり使うか「ファイル」→「終了」で閉じてください。再度セットアップする場合は、先にmoyAIを終了します。ログは更新・アンインストール後も同じ場所に残ります。

固定版WebView2とapp-local Visual C++を同梱した配布物は、同梱のランタイムを使用します。社内導入済みランタイムを使う配布物では、WebView2とVisual C++ x64が不足すると必要なものを表示します。社内の配布担当へその表示を渡してください。セットアップは不足物をインターネットから取得しません。スクリプト実行が組織のポリシーで禁止されている場合も、社内配布担当による許可・集中配布が必要です。

Windows 10で固定版WebView2 120以降を使う場合、セットアップは同梱ランタイムのフォルダーだけに必要なアプリコンテナーの読込み・実行権限を設定します。起動時の検査では権限を変更しません。不足の案内が出たら、元の配布物のセットアップから導入し直してください。固定版WebView2はネットワーク共有上から実行できないため、共有から受け取った一式もこのPCへ導入します。

アプリをインストールせず使う場合も、同じ配布物の共通helperは必要です。管理者が展開先の `scripts/Setup-Sandbox.ps1` を64bitのWindows PowerShell 5.1（`powershell.exe`）から管理者権限で実行した後、通常の権限で `Start-moyAI.cmd` を開きます。PowerShell 7（`pwsh.exe`）での共通helperの管理処理は受け付けません。展開したフォルダーはファイルを抜き出さず、そのまま保管してください。この使い方でも、設定・PCの接続情報・履歴は現在のWindows利用者のAppDataに保存します。コマンドラインから使う場合は `app/bin/moyai.exe` を起動します。通常のDesktop操作では、仕事の実行プログラム（Runner）を別に起動する必要はありません。

Hub同梱版では「チーム環境を用意する」からHubの管理画面を開けます。スタートメニューの「moyAI Team Management」からも開けます。同じWindows利用者の保存済み設定を使い、その保存先のHubが既に動いていれば同じHubへ接続します。Hubが含まれていない配布物では、同梱版の導入案内を表示します。仕事を依頼するだけのPCにはHubの導入は不要です。

チームのHubはセットアップした固定の導入先から使ってください。新しいZIPの展開先から毎回起動すると、Windowsの受信許可が古い実行ファイルの場所を指したままになることがあります。初回はHubの「PCの接続」でLANと受信許可を確認し、別PCのDesktopから実際に接続できるところまで確かめます。同じ導入先への通常更新では実行ファイルのパスを維持します。Hubの起動成功だけでは、別PCからの接続成功を意味しません。

管理者から受け取った `hub-config.moyai-join` は、セットアップ後にブラウザーのダウンロード欄やエクスプローラーから開けます。Desktopに表示された接続先と公開CA（接続先を確認するための証明書）を確認し、PCの参加を申請します。管理者がPCの参加を許可し、プロジェクトの操作PC・実行PCに指定すると利用できます。接続ファイルを開く操作だけでは、PCの参加承認やプロジェクトへの割当は完了しません。キャンセルすれば接続設定を変更しません。

既にDesktopが動いていれば同じウィンドウへ渡します。登録済みの同じ接続情報なら再接続します。同じ公開CAを使う同じHubのURL・ポート変更は、確認画面を経て、保存前に既存の端末資格で移動先を検証します。登録ID・秘密鍵・利用者との対応・実行許可・履歴は保持します。同じ接続の更新で別Hubや別CAへは移動しません。別Hubへ登録し直す場合はDesktopの「接続設定をリセット」を使い、新しい接続ファイルを読み込みます。旧Hubが応答しなくてもリセットでき、ローカル会話・成果・手入力AI設定は保持します。移動先の検証失敗時も元の接続設定を保持します。

このPCが仕事を実行する場合は、先に受付を一時停止し、実行中・状態不明の仕事を解消してください。Runner自身が仕事のない状態を確認して正常終了した後に接続先を保存し、新しい接続先で再起動しても受付停止を保持します。接続を確認してから明示的に受付を再開してください。停止後に保存が失敗した場合は元の接続設定が残り、受付を自動再開しません。

専用の `.moyai-join` だけを現在のWindows利用者へ関連付けます。既に別のアプリやWindowsの既定アプリ指定があれば、その設定を保持して案内を表示します。portable版や関連付けを使えない環境では、`Start-moyAI.cmd --join-config "C:\配布\hub-config.moyai-join"` またはDesktopの接続ファイル読込みを使えます。従来の `hub-config.toml` も読込み可能で、`.toml`全体の既定アプリは変更しません。

## 更新・アンインストール

更新前に、仕事を実行するPCで新しい仕事の受付を一時停止し、実行中の仕事が終わり、停止を確認できない処理がないことを確認します。その後、次の表に従って今回更新するアプリを終了してください。共通helperも更新する場合は、別の導入先や別Windows利用者を含め、このPCのすべてのmoyAI Desktop・CLI・Runnerを終了します。サービスが動いている間、共通helperの更新・削除は拒否します。

| セットアップに表示されるもの | 終了する方法 |
| --- | --- |
| moyAIの画面 | 「ファイル」→「終了」、またはタスクトレイのmoyAIアイコンから「終了」。このPCの接続中Runnerの仕事・保持アプリを正常停止し、Runnerの実プロセス終了を確認してから画面も終了します。×はトレイ格納で、仕事は続きます。 |
| 仕事の実行機能（Runner） | 通常は上のDesktopの「終了」で一緒に終了します。この終了連携を含まない従来の配布物、またはCLIだけで運用する場合は、下の手順で現在のRunnerを確認して終了します。 |
| チーム管理（Hub） | Hub管理者が、表示された導入先の `hub/bin/moyai-hub.exe --stop` を実行します。独自の保存先を使う場合は起動時と同じ `--data-dir` も指定します。ブラウザーを閉じたりHubのネットワークだけを停止したりしても、Hub本体は終了しません。 |

従来版からの更新では、新しい終了連携は更新前のDesktopには反映されません。Runnerが残っている場合は、同じWindows利用者のPowerShellで、セットアップに表示された導入先を使います。`identity` の応答の `runner_id` を確認し、その値を `shutdown --runner` へ渡します。実行中の仕事がある状態で終了すると中断するため、先に上記の受付停止と完了確認を行ってください。保存先を環境変数で切り替えている運用では、起動時と同じ環境で実行します。

```powershell
& "$env:LOCALAPPDATA\Programs\moyAI\app\bin\moyai-runner.exe" identity
# 下の値を、直前に表示された runner_id に置き換えます。
& "$env:LOCALAPPDATA\Programs\moyAI\app\bin\moyai-runner.exe" shutdown --runner '表示されたrunner_id'
```

新しいZIPを**既存の導入先の外**へ展開し、新しい `Setup-moyAI.cmd` を実行します。まだアプリが動いていれば、セットアップは名前・PID・実行ファイルの場所と終了手順を表示して中止します。セットアップが仕事やアプリを強制停止することはありません。表示されたアプリの終了を確認してから、同じセットアップを開き直してください。

Hub同梱版の更新には対応するHub同梱版を使います。Desktopだけの配布物で既存のチーム管理を黙って取り除く更新は拒否します。

新しいアプリ一式を検査してから導入先を入れ替えます。既定のexeパスは更新しても変わりません。以前のアプリ配置は `moyAI.previous-*` として同じ親フォルダーに残すため、必要なファイルがないことを確認してから削除できます。旧バイナリーへの起動切替が、移行済みデータとの互換性を保証するわけではありません。

共通helperの実行物またはruntime一式が変わる更新では管理者承認が必要です。同じ実行物なら再承認しません。交換中はサービスの新規開始を無効にし、失敗時には旧実行物とサービス設定を戻します。復元を確認できない場合は保護された退避先を残して中止し、強制停止や他サービスの変更は行いません。共通helperの更新後に利用者側アプリの導入が失敗した場合は、同じ新配布物のSetupを再実行してください。古いアプリを手動で戻す場合も、共通helperとの一致が必要です。

Hubの管理画面からWindowsの受信許可を追加した場合は、アンインストールや設置先の移動の前に、元のHubのネットワークを稼働させた状態で「表示中の既存ルールを解除」を実行し、解除を確認してからHubを停止します。SetupはFirewallルールを解除しません。詳しくはHubの[受信許可の手順](../../../moyAI-Hub/docs/firewall.md)を参照してください。

`Setup-moyAI.cmd -Uninstall` はアプリ配布時と内容が一致するファイルを取り除きます。変更されたファイル・追加されたファイルは残します。設定・本人資格・端末の鍵・Hub CA・履歴・成果・作業フォルダーは、更新とアンインストールで初期化しません。別のWindows利用者への資格移行も行いません。

この利用者別アンインストールでは、PC共通の `MoyAISandbox` とProgram Filesのhelperを残します。他の利用者も含め、このPCでmoyAIを使わなくなった場合だけ、すべてのDesktop・CLI・Runnerを終了し、管理者権限の64bit Windows PowerShell 5.1で信頼できる配布物の次のコマンドを実行します。共通helperの削除には管理者承認が必要です。サービスが稼働中、登録先や権限が想定と異なる、知らないファイルがある場合は削除せず中止します。

```powershell
& 'C:\配布\moyAI\scripts\Setup-Sandbox.ps1' -Uninstall
```

この管理処理は、他サービス、ProgramDataの実行PC登録・共通資源設定、各利用者のAppDataを変更しません。共通helperを再び使う場合は、利用する版の配布物から導入し直します。

Windowsへのサインイン時にRunnerやHubを自動起動する設定も、今回取り除くアプリに対してmoyAIが登録したものだけ解除します。Hubを複数の保存先で使っている場合も、取り除く実行ファイルへの登録だけが対象です。別の導入先・変更された実行ファイル・独自の起動コマンドは保持します。`-Uninstall -CheckOnly` で解除対象を確認できます。独自の自動起動設定は、その設定元で解除してください。

接続ファイルの関連付けも、導入記録と現在の登録値が一致するこの配置のものだけ解除します。別の起動コマンド・変更された登録値・Windowsで選び直した既定アプリは保持し、Windowsの保護された `UserChoice` は変更しません。

スタートメニューのショートカットも、起動先・引数・作業フォルダー・アイコンが今回の導入先の登録内容と一致するものだけ削除します。別の導入先を指すリンクと変更されたリンクは残します。Desktopだけの配布物を別のフォルダーへ導入しても、既存のHubを指す「moyAI Team Management」は削除しません。`-Uninstall -CheckOnly` でショートカットの削除対象も確認できます。

`app/maintenance/moyai-cleanup.exe` は保守用です。引数なしでは削除対象の一覧を表示し、削除は行いません。保存データを初期化する場合だけ、バックアップと対象確認後に `--reset-user-data --confirm-delete` の両方を指定します。通常の再接続・更新・アンインストールには使いません。

## 配布を作る担当者向け

`Setup-moyAI.cmd` は対話操作用で、成功・失敗ともキー入力を待ち、確認後も元の終了コードを返します。自動配布や検査には、配布物内の `scripts/Setup-moyAI.ps1` を直接実行してください。通常は初期画面の起動確認まで行います。非対話の集中配布では `-SkipStartupCheck` を指定すると配置だけを行い、起動確認を省略したことを表示します。`-CheckOnly` は検査だけ、`-Uninstall` は削除だけを行い、どちらも起動しません。`-NoShortcuts` を指定した場合は、次回から導入先の `Start-moyAI.cmd` で開けます。

```powershell
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" `
  -NoProfile -ExecutionPolicy Bypass -File .\scripts\Setup-moyAI.ps1 -CheckOnly
```

`scripts/package-release.ps1` は既定で閉域用の同梱ランタイムを要求します。配布許諾を確認した**展開済みx64固定版WebView2のディレクトリー**を `-WebView2FixedRuntimePath`、**app-local再配布用のx64 VC++ DLLディレクトリー**を `-VcRuntimePath` に指定します。VC++資材のDLLは直下の `vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll` の3本に限定します。別のDLLや不足があればpackage作成前に拒否し、余分なDLLを黙ってコピー・除外しません。システムにあるDLLを自動採取しません。必要な配布元のライセンス・通知類は資材ディレクトリーとともに保管・提供してください。

```powershell
.\scripts\package-release.ps1 -Version 3.0.3 `
  -WebView2FixedRuntimePath C:\release-inputs\WebView2-x64 `
  -VcRuntimePath C:\release-inputs\VC143.CRT-x64 `
  -ManualGuiStResultsPath C:\evidence\desktop-results.md
```

既設の社内ランタイムを前提にする場合は、明示的に `-RuntimeMode Installed` を使います。これはランタイムがない新PCで動くという証拠にはなりません。どちらも開発用Rust・Nodeを利用先へ要求しません。

Hubを同梱する場合は `-HubBinaryPath`、`-HubBuildIdentityPath` を渡します。Hub build identity JSONには `version`、40文字の `git_commit`、バイナリーの小文字 `sha256`、`source_clean` を記録します。配布スクリプトは実際のファイルのhashを照合し、`deployment.json` にDesktopとHubのidentityを記録します。**identity記録だけで互換性確認済みにはしません。** 公開用には `-HubCompatibilityResultsPath` の実際の組合せ試験結果に次の完全一致行も必要です。

```text
Desktop Hub Gate: PASS
Desktop Git Commit: <Desktopの40文字commit>
Hub Git Commit: <Hubの40文字commit>
Hub SHA256: <Hub実行ファイルの64文字SHA256>
```

Hub同梱時は、同じHubソースの `docs` から準備・受信許可・Web管理の3ガイドも `hub/docs` へ同梱し、この導入手順とのリンクを配布物内で解決します。既定の参照元は隣の `moyAI-Hub/docs` です。別の配置でビルドした場合は `-HubDocumentationPath` を指定してください。必要なガイドが欠けている場合はビルド前に中止します。Desktop単体の配布にはHubソースを要求せず、Hub手順の参照先は公式リポジトリーになります。

Hubの初期設定ファイル `web-management.json` も、実行ファイルと同じ `hub/bin` へ同梱します。既定の参照元は `-HubDocumentationPath` の親フォルダーにある同名ファイルです。外部のビルド入力など別の配置を使う場合は `-HubWebSettingsPath` を指定してください。ファイルがなければビルド前に中止します。初期値は固定ポート9080・他端末向け公開OFFです。初回起動前に同梱ファイルの `settings.local_port` を変更でき、起動に成功した後はHubの保存先にある設定を使います。既存の保存設定は同梱ファイルで上書きしません。

未公開の診断packageのみ既存の `-SkipManualGuiStGate` を使えます。同梱資材の存在・x64形式・checksumの検査はfresh PCの実行証拠ではありません。実ランタイムを用いた新PC導入、実Desktop、同梱Hub、最初の仕事、更新後の保持を別途確認します。package manifestの `fresh_pc_verified` は、このスクリプトだけでは常に `false` です。
