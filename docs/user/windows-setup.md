# Windowsへの導入と更新

この手順は、`Setup-moyAI.cmd` と `deployment.json` を含む開発版配布物に適用します。旧v2.1.1 ZIPの配置は変更されません。実行先はWindows 10以降のx64です。

まず全員が下の「導入して開く」を行い、その後は担当に合った入口を選んでください。同じ人やPCが複数を担当することもできます。

| 担当すること | 初回画面で選ぶ入口 | 用意するもの・次の作業 |
| --- | --- | --- |
| WinAから仕事を依頼し、結果を見る | チームに参加する | 管理者から接続ファイル・利用者名・本人設定コードを受け取り、[チームへの参加手順](../desktop-first-use.md#チームで使う)を進めます。このPCのAI・モデル設定とHub本体は不要です。 |
| WinBで仕事を実行する | チームの仕事をこのPCで実行する | 実行するAIの接続先とモデル、管理者からの接続ファイルを用意します。AI設定後にPCの参加を申請し、承認後に[保存先と操作の許可](../shared-work-desktop.md#このPCで仕事を実行する)を設定します。Hub管理者がこのPCをプロジェクトへ割り当てます。 |
| チームのHubを管理する | チーム環境を用意する | Hub同梱版を使い、[管理者の準備手順](../../../moyAI-Hub/docs/team-preparation.md)で接続・利用者・プロジェクトを設定します。 |
| このPCだけで個人の仕事をする | 自分のPCで使う | 利用するAIの接続先とモデルを設定します。Hubへの参加は不要です。 |

最初の仕事には、管理者による利用者とPCの割当、WinBの実行設定が必要です。インストール後にWinAだけを操作しても、これらの準備は完了しません。

## 導入して開く

1. 社内の信頼できる配布元から一式を受け取り、ZIPをフォルダーごと展開します。配布元が示すZIPのSHA256も確認します。
2. `Setup-moyAI.cmd` を開きます。現在のWindows利用者の `%LOCALAPPDATA%\Programs\moyAI` に配置し、スタートメニューへ「moyAI」を追加します。管理者権限やネットからのダウンロードは使いません。
3. 「導入が完了しました」と次に開くものを確認します。画面は自動では閉じません。任意のキーを押して閉じ、**Windowsのスタートメニューから「moyAI」**を開きます。セットアップはmoyAIを自動起動しません。
4. 初回画面では上の表に合った入口を選びます。導入完了だけでは、PC参加・本人設定・仕事の実行準備は完了しません。

完了できなかった場合も表示は残ります。原因と「次の操作」を確認してから閉じてください。解消しない場合は、表示全体と導入先を社内の配布担当へ伝えます。設定や履歴を初期化する必要はありません。

固定版WebView2とapp-local Visual C++を同梱した配布物は、同梱のランタイムを使用します。社内導入済みランタイムを使う配布物では、WebView2とVisual C++ x64が不足すると必要なものを表示します。社内の配布担当へその表示を渡してください。セットアップは不足物をインターネットから取得しません。スクリプト実行が組織のポリシーで禁止されている場合も、社内配布担当による許可・集中配布が必要です。

Windows 10で固定版WebView2 120以降を使う場合、セットアップは同梱ランタイムのフォルダーだけに必要なアプリコンテナーの読込み・実行権限を設定します。起動時の検査では権限を変更しません。不足の案内が出たら、元の配布物のセットアップから導入し直してください。固定版WebView2はネットワーク共有上から実行できないため、共有から受け取った一式もこのPCへ導入します。

インストールせず使う場合は、展開先の `Start-moyAI.cmd` を開きます。展開したフォルダーはファイルを抜き出さず、そのまま保管してください。この使い方でも、設定・ログイン情報・履歴は現在のWindows利用者のAppDataに保存します。コマンドラインから使う場合は `app/bin/moyai.exe` を起動します。通常のDesktop操作では、仕事の実行プログラム（Runner）を別に起動する必要はありません。

Hub同梱版では「チーム環境を用意する」からHubの管理画面を開けます。スタートメニューの「moyAI Team Management」からも開けます。同じWindows利用者の保存済み設定を使い、その保存先のHubが既に動いていれば同じHubへ接続します。Hubが含まれていない配布物では、同梱版の導入案内を表示します。仕事を依頼するだけのPCにはHubの導入は不要です。

管理者から受け取った `hub-config.moyai-join` は、セットアップ後にブラウザーのダウンロード欄やエクスプローラーから開けます。Desktopに表示された接続先と公開CA（接続先を確認するための証明書）を確認し、PCの参加を申請します。その後は同じ画面で本人設定とプロジェクトへの参加を進めます。接続ファイルを開く操作だけでは、PCの参加承認や本人のログインは完了しません。キャンセルすれば接続設定を変更しません。

既にDesktopが動いていれば同じウィンドウへ渡します。登録済みの同じ接続情報なら再接続します。同じ公開CAを使う同じHubのURL・ポート変更は、確認画面を経て、保存前に既存の端末資格で移動先を検証します。登録ID・秘密鍵・本人の継続ログイン・実行許可・履歴は保持します。別Hubへの移動や公開CA変更には対応せず、検証失敗時も元の接続設定を保持します。

このPCが仕事を実行する場合は、先に受付を一時停止し、実行中・状態不明の仕事を解消してください。Runner自身が仕事のない状態を確認して正常終了した後に接続先を保存し、新しい接続先で再起動しても受付停止を保持します。接続を確認してから明示的に受付を再開してください。停止後に保存が失敗した場合は元の接続設定が残り、受付を自動再開しません。

専用の `.moyai-join` だけを現在のWindows利用者へ関連付けます。既に別のアプリやWindowsの既定アプリ指定があれば、その設定を保持して案内を表示します。portable版や関連付けを使えない環境では、`Start-moyAI.cmd --join-config "C:\配布\hub-config.moyai-join"` またはDesktopの接続ファイル読込みを使えます。従来の `hub-config.toml` も読込み可能で、`.toml`全体の既定アプリは変更しません。

## 更新・アンインストール

更新前に、仕事を実行するPCで新しい仕事の受付を一時停止し、実行中の仕事が終わり、停止を確認できない処理がないことを確認します。その後、次の表に従って今回更新するアプリを終了してください。別の導入先のアプリは対象ではありません。

| セットアップに表示されるもの | 終了する方法 |
| --- | --- |
| moyAIの画面 | タスクトレイのmoyAIアイコンから「終了」。画面の×だけでは終了しません。 |
| 仕事の実行機能（Runner） | 実行PCの担当者が、下の手順で現在のRunnerを確認して終了します。Desktopを終了してもRunnerは動き続けます。 |
| チーム管理（Hub） | Hub管理者が、表示された導入先の `hub/bin/moyai-hub.exe --stop` を実行します。独自の保存先を使う場合は起動時と同じ `--data-dir` も指定します。ブラウザーを閉じたりHubのネットワークだけを停止したりしても、Hub本体は終了しません。 |

Runnerを終了する場合は、同じWindows利用者のPowerShellで、セットアップに表示された導入先を使います。`identity` の応答の `runner_id` を確認し、その値を `shutdown --runner` へ渡します。実行中の仕事がある状態で終了すると中断するため、先に上記の受付停止と完了確認を行ってください。保存先を環境変数で切り替えている運用では、起動時と同じ環境で実行します。

```powershell
& "$env:LOCALAPPDATA\Programs\moyAI\app\bin\moyai-runner.exe" identity
# 下の値を、直前に表示された runner_id に置き換えます。
& "$env:LOCALAPPDATA\Programs\moyAI\app\bin\moyai-runner.exe" shutdown --runner '表示されたrunner_id'
```

新しいZIPを**既存の導入先の外**へ展開し、新しい `Setup-moyAI.cmd` を実行します。まだアプリが動いていれば、セットアップは名前・PID・実行ファイルの場所と終了手順を表示して中止します。セットアップが仕事やアプリを強制停止することはありません。表示されたアプリの終了を確認してから、同じセットアップを開き直してください。

Hub同梱版の更新には対応するHub同梱版を使います。Desktopだけの配布物で既存のチーム管理を黙って取り除く更新は拒否します。

新しいアプリ一式を検査してから導入先を入れ替えます。既定のexeパスは更新しても変わりません。以前のアプリ配置は `moyAI.previous-*` として同じ親フォルダーに残すため、必要なファイルがないことを確認してから削除できます。旧バイナリーへの起動切替が、移行済みデータとの互換性を保証するわけではありません。

Hubの管理画面からWindowsの受信許可を追加した場合は、アンインストールや設置先の移動の前に、元のHubのネットワークを稼働させた状態で「表示中の既存ルールを解除」を実行し、解除を確認してからHubを停止します。SetupはFirewallルールを解除しません。詳しくはHubの[受信許可の手順](../../../moyAI-Hub/docs/firewall.md)を参照してください。

`Setup-moyAI.cmd -Uninstall` はアプリ配布時と内容が一致するファイルを取り除きます。変更されたファイル・追加されたファイルは残します。設定・本人資格・端末の鍵・Hub CA・履歴・成果・作業フォルダーは、更新とアンインストールで初期化しません。別のWindows利用者への資格移行も行いません。

Windowsへのサインイン時にRunnerやHubを自動起動する設定も、今回取り除くアプリに対してmoyAIが登録したものだけ解除します。Hubを複数の保存先で使っている場合も、取り除く実行ファイルへの登録だけが対象です。別の導入先・変更された実行ファイル・独自の起動コマンドは保持します。`-Uninstall -CheckOnly` で解除対象を確認できます。独自の自動起動設定は、その設定元で解除してください。

接続ファイルの関連付けも、導入記録と現在の登録値が一致するこの配置のものだけ解除します。別の起動コマンド・変更された登録値・Windowsで選び直した既定アプリは保持し、Windowsの保護された `UserChoice` は変更しません。

`app/maintenance/moyai-cleanup.exe` は保守用です。引数なしでは削除対象の一覧を表示し、削除は行いません。保存データを初期化する場合だけ、バックアップと対象確認後に `--reset-user-data --confirm-delete` の両方を指定します。通常の再接続・更新・アンインストールには使いません。

## 配布を作る担当者向け

`Setup-moyAI.cmd` は対話操作用で、成功・失敗ともキー入力を待ち、確認後も元の終了コードを返します。自動配布や検査には `scripts/Setup-moyAI.ps1` を直接実行してください。`-CheckOnly` は検査だけを行い、導入・起動しません。`-NoShortcuts` を指定した場合は、完了表示に出る導入先の `Start-moyAI.cmd` から開けます。

```powershell
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" `
  -NoProfile -ExecutionPolicy Bypass -File .\scripts\Setup-moyAI.ps1 -CheckOnly
```

`scripts/package-release.ps1` は既定で閉域用の同梱ランタイムを要求します。配布許諾を確認した**展開済みx64固定版WebView2のディレクトリー**を `-WebView2FixedRuntimePath`、**app-local再配布用のx64 VC++ DLLディレクトリー**を `-VcRuntimePath` に指定します。VC++には `vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll` が必要で、そのディレクトリーのDLL一式をコピーします。システムにあるDLLを自動採取しません。必要な配布元のライセンス・通知類は資材ディレクトリーとともに保管・提供してください。

```powershell
.\scripts\package-release.ps1 -Version 3.0.0 `
  -WebView2FixedRuntimePath C:\release-inputs\WebView2-x64 `
  -VcRuntimePath C:\release-inputs\VC143.CRT-x64 `
  -ManualGuiStResultsPath C:\evidence\desktop-results.md
```

既設の社内ランタイムを前提にする場合は、明示的に `-RuntimeMode Installed` を使います。これはランタイムがない新PCで動くという証拠にはなりません。どちらも開発用Rust・Nodeを利用先へ要求しません。

Hubを同梱する場合は `-HubBinaryPath`、`-HubBuildIdentityPath` を渡します。Hub build identity JSONには `version`、40文字の `git_commit`、バイナリーの小文字 `sha256`、`source_clean` を記録します。配布スクリプトは実際のファイルのhashを照合し、`deployment.json` にDesktopとHubのidentityを記録します。**identity記録だけで互換性確認済みにはしません。** 公開用には `-HubCompatibilityResultsPath` の実際の組合せ試験結果に次の完全一致行も必要です。

```text
Desktop Hub Gate: PASS
Desktop Git Commit: <Desktopの40文字commit>
Hub Git Commit: <Hubの40文字commit>
Hub SHA256: <Hub実行ファイルの64文字SHA256>
```

未公開の診断packageのみ既存の `-SkipManualGuiStGate` を使えます。同梱資材の存在・x64形式・checksumの検査はfresh PCの実行証拠ではありません。実ランタイムを用いた新PC導入、実Desktop、同梱Hub、最初の仕事、更新後の保持を別途確認します。package manifestの `fresh_pc_verified` は、このスクリプトだけでは常に `false` です。
