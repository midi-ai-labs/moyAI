# moyAIを使い始める

現行開発版（Desktop 3.0.0）の手順です。公開済みv2.1.1を使う場合は、その配布物のREADMEを参照してください。Windowsへの導入・更新は[専用手順](windows-setup.md)にまとめています。

## 入口を選ぶ

`Setup-moyAI.cmd` で導入し、スタートメニューからmoyAIを開きます。インストールせず使う場合は、ZIP全体を展開して `Start-moyAI.cmd` を開きます。

| したいこと | 初回画面で選ぶ項目 | 次に行うこと |
| --- | --- | --- |
| このPCで作業する | 自分のPCで使う | AIの接続先とモデルを保存する |
| チームの仕事を依頼する | チームに参加する | Hubの接続ファイルを読み込む |
| このPCでも仕事を実行する | チームの仕事をこのPCで実行する | Hubへ参加し、実行許可とフォルダーを設定する |
| チームのHubを用意する | チーム環境を用意する | 同梱Hubの管理画面を開く |

Hubの準備は管理者向けの[チーム準備手順](../../../moyAI-Hub/docs/team-preparation.md)を参照してください。通常の利用にmoyAIのID・パスワードは不要です。

## 自分のPCで使う

1. LM Studio、oMLXなどの外部AIサーバーを使える状態にします。moyAIはサーバーやモデルを起動しません。
2. 初回画面、または **設定 → AIの接続** で接続方式とURLを入力します。LM StudioのResponses API、oMLX等のOpenAI互換Chat Completionsなど、ホストが提供する方式を選びます。
3. 「モデル読込」で候補を取得するか、モデルIDを入力します。必要なAPIキーは、保持する環境変数の名前を指定します。キー本体は入力しません。
4. 操作権限を確認して保存します。メインとサイドチャットの接続は別々に設定します。
5. 左のプロジェクト一覧へ作業フォルダーを追加して、依頼を入力します。ファイル作業を伴わない会話はチャットから始められます。

既存の作業フォルダーを選べます。AIが必要に応じて中身や指示ファイルを読み、作業を進めます。Gitプロジェクト内の一部のフォルダーを選んだ場合も、選択した場所が作業範囲になります。

## チームで使う

1. 管理者から `hub-config.moyai-join` を受け取り、ダブルクリックします。関連付けがない場合は **moyAI Hub → PCの接続** で読み込みます。
2. 表示された接続先を確認して参加を申請します。管理者がPCの登録と、プロジェクトの操作・実行用途を許可します。同じWindowsユーザー名のPCも別の端末です。
3. 実行PCでは、実行を許可し、プロジェクトごとに作業フォルダーを登録します。依頼だけをするPCにはこの設定は不要です。
4. 左の **プロジェクト** に表示された `MCP` 印付きのプロジェクトを開き、新しいチャットから依頼します。
5. 必要な操作承認に答え、回答と成果ファイルを確認します。

依頼文の例は「WinAとWinBを使い、WinBをホストとしてFlaskのTODOアプリを作ってください」です。PCはHubであらかじめ許可し、それぞれの作業フォルダーを登録しておきます。依頼ごとの実行PCや工程を入力欄で設定する必要はありません。AIはプロジェクト内で許可されたPCを利用できます。

Hubへ接続したPCのAI設定は、共通の **AIの接続** に表示されます。URLを各PCへ入力せず、Hubの標準モデルまたは登録済みモデルを選びます。Runnerは実行PCのメインの選択を使います。Hub停止中に別のAIへ自動では切り替わりません。

Hubプロジェクトの一覧・会話・離脱などの操作は[Hubプロジェクトの操作](../shared-work-desktop.md)を参照してください。離脱やHubでの参加解除はフォルダーを削除しません。再参加は新しい参加として設定し、以前の参加設定を自動復元しません。

## 会話を進める

- 依頼と追加入力は同じチャット欄から送ります。処理中は進捗・ツール操作を確認できます。
- 停止ボタンで処理を止めた後、最新の発言を編集して再送できます。過去の発言、ローカル会話の画像付き発言、Hub会話の添付付き発言は文字編集対象外です。
- 編集・停止で実ファイルや起動済みアプリは巻き戻りません。保持中のアプリは個別の停止操作で確認します。
- 出力欄で生成ファイルを確認します。共有の成果は公開されたファイルで、端末のフォルダー全体を自動同期するものではありません。
- サイドチャットはメイン会話の内容について質問する補助欄です。ツールを実行せず、メインの作業を変更しません。

別PCの仕事を受信中のDesktopには使用中表示と現地停止が表示されます。使用中のPCでの新規実行は制限され、入力中の下書きは保持されます。通信断や停止要求の受付だけでは、実プロセスが停止したとは判断しません。

## 操作の許可

| 設定 | 動作 |
| --- | --- |
| 承認を求める | 確認が必要な操作を利用者へ提示する |
| 代理で承認 | AIが審査し、代理で判断できない操作だけ利用者へ確認する |
| フルアクセス | 現在のWindows利用者の権限で実行する |

前二つはWindowsの作業フォルダー保護を使います。完全なOS隔離ではありません。確認画面では対象ファイルや実行コマンドを確認し、許可・拒否・停止を選びます。共有仕事の承認は権限のある担当者または管理者がDesktopで判断し、実行PCが許可した範囲を超える権限は追加しません。

代理承認から確認を求められた場合も、許可するまでその操作は実行されません。許可は表示された一回の操作に適用されます。拒否・中止すると処理を止め、次の指示を待ちます。明示した禁止や権限不足を、確認ボタンで解除することはできません。

## 終了・再開と設定の保存

Desktopの×ボタンはトレイへ格納します。もう一度起動すると同じウィンドウへ戻ります。完全終了はトレイの **終了** です。RunnerやHubは別に動作するため、更新時には[終了手順](windows-setup.md#更新アンインストール)を使ってください。

Windowsの共通設定は `%APPDATA%\midi-ai-labs\moyai\config\config.toml` へ保存されます。選択したローカル会話には別途セッション設定を適用できます。未保存の入力はアプリ終了後の保持を前提にしないでください。会話記録とプロジェクト内の実ファイルは別に保存されます。

## 接続できないとき

1. Hub登録の有無に応じて **AIの接続** または **PCの接続** を確認します。モデル一覧の取得成功だけでは、実際の生成成功は分かりません。
2. ホスト名を解決できない場合は、ネットワーク管理者が指定した到達可能な名前またはIPを確認します。`127.0.0.1` はそのアプリを動かすPC自身です。
3. Hub利用ではHub・Gateway・AIホスト・実行PCの稼働と、Hub PCの受信許可を確認します。
4. Hubの再インストールなどで登録し直す場合は **接続設定をリセット** を使えます。旧Hubが応答しなくても実行でき、手入力のAI設定・ローカル会話・成果を保持します。新しいHubの参加と実行許可は改めて行います。

詳細は[端末接続](../hub-device-network-guide.md)、[設定例](../../config.example.toml)、[共有Runner](../runner-shared.md)を参照してください。CLI/TUIの入口は[README](../../README.ja.md#clitui)にあります。
